### 3.2 Paths, state, results, and compatibility

**Path identity.** Distinguish requested target, logical project root, process cwd, registered project ID, and staged execution root. CLI relative input uses invocation-start cwd exactly once. MCP relative input uses declared project/workspace root; no declared root means server-start cwd, stated in schema/help. Absolute paths preserve identity. Root resolution prefers explicit registered root, then nearest containing Rush config/project descriptor or Git worktree root, then requested directory/file parent. Ambiguous conflicting registrations produce a named error. Physical containment, symlink checks, staging snapshots, and configuration identity stay enforced; never replace them wholesale with current cwd.

**State.** Project memory/cache/results live under resolved logical root. Platform data-root registry, verified toolchains, process ownership, and service records remain legitimate global state. Read-only queries create no directory, DB, journal, cursor key, migration, telemetry, or registration. Permission checks precede constructor side effects. A missing store is an empty display with a reason, not an implicitly initialized store.

**Result contract.** Keep existing ToolStatus values and raw operation envelopes. Legacy extension locations are `metadata.scope`, `metadata.engines`, `metadata.delivery`, and optional `metadata.memory`; strict V1 locations are `extensions.metadata.*`, matching current `adapt_legacy_tool_result` without a new top-level key. Scope version is integer 1; it includes requested roots/targets, logical root, actual execution cwd, requested/matched/consumed file counts, dependencies, excluded/skipped reasons, and coverage state `complete|partial|none|unavailable`. Count unique normalized physical files, with aliases recorded; dependency consumption is separate from requested targets. Missing instrumentation means unavailable with reason, never guessed matched=consumed. Non-file operations report kind=operation, file_count=null, and reason=not_file_analysis.

Per-engine entries retain engine, executable identity, version or version-unavailable reason, config identity, analysis environment, status, summary, skip/error reason, and scope. Missing engine has no invented version. Multi-engine result retains every child. All-success executed work is ok; findings preserve existing warn/fail semantics; no work is skipped; partial required execution is at least warn; invocation/engine failures are error. Precedence is error > fail > warn > skipped > ok, with mixed ok+skipped promoted to warn. CLI exits are ok/skipped=0, warn/fail=1, error=2; malformed CLI option syntax remains Click usage error=2. Tests assert exact values. Collection/list operations may return ok with zero rows; that is not a claim of completed quality analysis.

Memory attribution is `memory={version:1,used:[{id,revision,source,operation}],written:[{id,revision,source,operation}]}`. Include only actually consumed evidence and committed writes, after successful access checks. Deduplicate by id/revision/operation, preserving first-use order and read versus write distinction. No content, capability, prompt, or secret is copied into attribution. Omit entire memory member if both arrays empty. Aggregation unions child receipts while preserving child attribution and project/session boundaries. Cache hits disclose original observation versus this invocation; do not manufacture new reads/writes.

**Output recovery.** T16 provides explicit `result_view="compact"`, default 50 findings and 32,768 UTF-8 bytes including envelope. Existing full CLI/JSON and legacy MCP remain available. Compact mode requires cache-write permission before engine execution so full immutable redacted evidence can be recovered through existing CCR mechanisms. No hidden grant or durable write on denial. Core guidance offers compact mode with explicit consent; without consent, explain available full mode. Status derives from complete analysis, never truncated display. Bounds, continuation and lifetime are specified in T16. Core `rush_status(operation="result", path, result_handle, view, cursor, offset, limit, max_bytes)` delegates the same shared retrieval as full-profile `rush_context_retrieve` and CLI `rush context retrieve`; no profile switch is needed to recover a core result. Ordinary status uses operation=status by default.
