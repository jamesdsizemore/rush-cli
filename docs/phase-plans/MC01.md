# MC01 — Version artifacts and make every mutation atomic

Evidence record for Phase 63 workstream MC01 (`docs/phase-plans/phase-63-memory-capabilities-vibecoder-plan.md` §9, MC01.1-MC01.5). Owned production files: `src/rush/memory/store.py`, `src/rush/memory/migration.py`, `src/rush/memory/expiry.py`, `src/rush/memory/maintenance.py`. Owned test file: `tests/test_memory_versions.py`.

## Schema

Two new tables, plus one additive column on the existing `memory_artifacts` table:

- `memory_artifacts.artifact_version INTEGER NOT NULL DEFAULT 1` — current version counter on the live row.
- `memory_artifact_versions(artifact_id, artifact_version, content, source, trust_tier, created_at, deleted)`, primary key `(artifact_id, artifact_version)` — immutable per-version snapshot; `deleted=1` marks a tombstone version.
- `memory_changes(sequence INTEGER PRIMARY KEY AUTOINCREMENT, artifact_id, artifact_version, tombstone, created_at)` — global monotonic change log; `sequence` is SQLite's `AUTOINCREMENT` counter, so it never repeats or goes backward across the whole store, not just per artifact.

Both new tables are created via `CREATE TABLE IF NOT EXISTS` inside `_SCHEMA_SQL`, so every fresh `TypedArtifactStore(project_root)` gets them immediately. The `artifact_version` column is included directly in `_SCHEMA_SQL`'s `CREATE TABLE memory_artifacts` for fresh databases, and additively backfilled via `TypedArtifactStore._migrate_version_column` (mirroring the pre-existing `_migrate_expiry_columns` pattern) for any pre-MC01 database opened through the normal read-write constructor.

## Atomic mutation path

`_write_version(conn, artifact_id, *, content, source, trust_tier, expected_version, tombstone=False)` (`store.py`) is the single shared writer. Given an already-open write transaction (`BEGIN IMMEDIATE`), it:

1. Reads the row's current `artifact_version`. Raises `KeyError` if the artifact doesn't exist.
2. If `expected_version` is not `None` and doesn't match the current version, raises `VersionConflictError(code="E_VERSION")` without writing anything.
3. Inserts one `memory_artifact_versions` row and one `memory_changes` row at `current_version + 1`.
4. Returns the new version; the caller persists it (and any other changed columns) onto `memory_artifacts` in the same transaction.

Routed callers (inspected every SQL mutation site in the four owned modules, not just the obvious store methods):

- `TypedArtifactStore.write` — inserts the row and its version-1 history directly (no prior row to lock).
- `TypedArtifactStore.update_content` — now takes `expected_version: int | None = None`; locks the row, routes through `_write_version`, then updates `content`/`artifact_version` together.
- `TypedArtifactStore.promote` / `promote_stored_artifact` — now takes `expected_version: int | None = None`; only advances the version when `decision.promoted` is true (a promotion is always a real semantic change, even if `content` is byte-identical).
- `TypedArtifactStore.delete` — now takes `expected_version: int | None = None`; captures the row's current content/source/trust_tier, calls `_write_version(..., tombstone=True)`, then deletes the row from `memory_artifacts` (the tombstone's provenance survives in `memory_artifact_versions`/`memory_changes` even though the live row is gone).
- `migration.replace_origin_content` — routes its UPDATE through `_write_version` only when content actually changed; the pre-existing equality check (`json.dumps(...) == json.dumps(...)`) still short-circuits identical imports as a no-op with zero version advance, unchanged from its prior behavior.
- `maintenance._mutate_promotion_sweep` — the promoted branch is already covered via `promote_stored_artifact`; the corroboration-count-only branch (no promotion, but `corroboration_count` changed) is separately routed through `_write_version`.
- `maintenance._mutate_staleness_sweep` — the `stale=1` UPDATE is routed through `_write_version`.
- `maintenance._mutate_skill_admission_check` — fully covered via `promote_stored_artifact`.
- `expiry.sweep_expired` — the `expires_at`/`expired_at`/`expired_by` UPDATE is routed through `_write_version`.

`expected_version` defaults to `None` everywhere so every pre-existing caller (`tests/test_phase61_store.py`, `tests/test_memory_compatibility_regressions.py`, `src/rush/tools/memory.py`, etc.) keeps working unchanged with no concurrency check.

## Read-only opening

`TypedArtifactStore.open_readonly(project_root) -> ReadOnlyOpenResult` never creates a directory, file, journal, or migrated schema:

- Missing DB: returns `available=False` after only a `Path.exists()` check — zero filesystem writes.
- Existing DB predating `artifact_version`: opens the connection in SQLite's URI `mode=ro`, reads `PRAGMA table_info`, and returns `available=True, migration_required=True` without writing anything.
- Existing, already-migrated DB: returns `available=True` with a live read-only `sqlite3.Connection`.

The DB path is percent-encoded (`urllib.parse.quote`) before being embedded in the `file:` URI, so project roots containing spaces or reserved URI characters (` `, `#`, `?`, `%`) still open correctly — exercised directly by `test_read_only_open_creates_no_files`'s `"project ?#% space"` fixture directory.

## Legacy migration and rollback safety

`TypedArtifactStore.upgrade(project_root, *, cache_write: bool)` is the explicit, opt-in migration entry point (raises `ValueError` if `cache_write` is not `True`). It opens its own plain (non-WAL) `sqlite3.connect()` — deliberately not `_init_db()`/`_SCHEMA_SQL`, so it never touches `PRAGMA journal_mode` — and inside one `BEGIN IMMEDIATE` transaction:

1. Adds `artifact_version` via `ALTER TABLE ... ADD COLUMN` if missing.
2. Creates `memory_artifact_versions`/`memory_changes` via individual `.execute()` calls (deliberately **not** `executescript()`, since `executescript()` implicitly commits any pending transaction first, which would silently defeat the rollback guarantee below).
3. Backfills one version-1 row per pre-existing `memory_artifacts` row via `TypedArtifactStore._backfill_legacy_row`, skipped entirely if `memory_artifact_versions` already has any rows (idempotent re-run).
4. Commits, returning the count of newly-backfilled rows.

On any exception (including inside `_backfill_legacy_row`), the transaction is rolled back and the exception re-raised. `test_migration_failure_rolls_back` verifies this at the byte level: after an injected `_backfill_legacy_row` failure, the on-disk `.db` file is byte-for-byte identical to its pre-`upgrade()` state, `artifact_version` is absent from the schema, and the original row's `id`/`content` are unchanged.

`test_legacy_migration_preserves_ids_origins_and_trust` verifies the success path: a legacy row's `id`, `origin_kind`, `origin_id`, and `trust_tier` are preserved exactly, `artifact_version` is `1`, and `memory_artifact_versions` records the original `content`/`source`/`trust_tier`.

## Concurrency

`test_concurrent_expected_version_rejects_lost_update` verifies the compare-and-swap contract end to end: two `TypedArtifactStore` instances both observe version 1; the first commits an update to version 2; the second's `update_content(..., expected_version=1)` raises `VersionConflictError` with `.code == "E_VERSION"`, leaves the row at version 2 with the first writer's content, and adds no extra `memory_changes` row (`change_count == 2`: one from the original `write()`, one from the first writer's successful `update_content`).
