# Rush whole-application review and continuation ledger

## Verdict and authority

**Not ready for the promised beginner workflow.** Rush has substantial reusable code, but installation, engine provisioning, complete scans, agent remediation, memory and interfaces do not form one working product journey. There are also reproducible data-loss, containment, false-clean and simulated-execution defects. A colorful interactive TUI and a project-selectable local web application are required product surfaces, not excluded scope.

Review baseline: `997b56e64bb2f72688cdd34252227a596f0fdb3d`, branch `codex/phase-61-62-review-fixes`, worktree `/Users/jamesdsizemore/Developer/rush-cli-worktrees/phase-61-62-review-fixes`. Production source was frozen during review. The review did not implement fixes, release anything, install hooks, run paid providers or change `main`. `AGENTS.md` was separately corrected to remove the UI prohibition at the user's explicit direction. Existing Phase 63 planning edits remain separate from implemented behavior.

This is a whole-application review, not a branch-diff review. Earlier narrow review instructions do not restrict this later approved scope. Applicable repository rules are in [AGENTS.md](../../AGENTS.md): shared implementations and stdio boundaries (lines 6–11), result and secret contracts (27–29), controlled side effects (30–31), catalog parity (36–38), and complete implementation/meaningful tests (67–71). Rule references below identify repository-specific support; other findings stand on observed correctness failures.

## Required product journey

One copyable installation command for each supported operating-system shell must install Rush without requiring a beginner to install Python or edit JSON, discover every locally detectable coding agent, register supported integrations without losing existing settings, activate scoped memory, and verify readiness. Unsupported or undetectable agent integrations must be listed with the exact limitation; claiming universal readiness after silently skipping an agent is prohibited.

From that installation, a user selects a repository, gets its languages/frameworks/workspaces and needed toolchains identified, installs applicable scanner and project dependencies through a reviewable plan, runs a comprehensive scan, receives one aggregate with all individual results and coverage gaps, sends bounded actionable findings to a connected agent, and verifies fixes with a rescan. Missing engines cannot become clean results. Local static work precedes model work; measured token use and savings provenance accompany the handoff.

Both the interactive TUI and local web application expose this journey. The web application has a persistent per-project selector. Each project contains overview, complete scan results, memory administration, token use, Git history and every other Rush-generated artifact, with appropriate redaction and access boundaries. Merely decorating current one-shot commands does not satisfy these requirements.

## Benchmark decision

Retain the [Phase 63 benchmark strategy](memory-capabilities-benchmark-strategy.md): established public memory/retrieval workloads plus Rush-specific real agent episodes. Public memory scores cannot prove installation, scanner coverage, correct fixes, project isolation or interface usability. Extend the existing `scripts/benchmarks/run.py` for the deterministic project journey and measured runs; do not create a competing benchmark framework.

Required measures: applicable/executed/blocked tool counts, seeded-defect recall, false-clean rate, result deduplication fidelity, install success per OS/architecture/agent, cancellation recovery, fix verification, retrieval quality, actual model tokens, payload tokens, cold/warm runtime and cache validity. Report estimates separately from provider usage. Claims of savings need matched tasks and quality retained; skipped work is never a saving. Phase plans specify concrete fixture and acceptance owners.
