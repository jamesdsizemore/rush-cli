## 2. Correct workflow design

The configuration below replaces the Phase 72 run. It is assembled from the correct-configuration column of section 3.

### 2.1 Before launch (one pass, no stop points)

| Step | Configuration |
|---|---|
| Constraints | Keep James's prohibitions verbatim in one ledger file: no GoalBuddy for this plan, no new behavior hooks, no push of an incomplete phase, never stop running work unasked, no open decisions, no descoped options. Check every proposed mechanism against it before proposing it. |
| Dependency graph | Build the task DAG once from the plan packet, the pregate `cross_task_decisions` and the design brief, recording the source of each edge. Run every ready node at once, each in its own worktree. Shared files are a merge cost, not a dependency. |
| Cost and time table | The script header lists each stage's agent count, model, expected tokens, wall budget and stop points. Stop points before first code = 0. Report the projected critical path with the plan. |
| Model tiers | Haiku: running commands, polling, markers by script. Sonnet: code maps, tests, merges, typing, fixes, verification. Codex CLI: every review lens. Opus: only the implementers the plan names as trust-boundary work. Justify each Opus agent in one line before launch. |
| Plumbing dry run | Run every gate script on a synthetic tree first. Cases: broken import, zero tests collected, a missing upstream file, a failed patch apply, a 3,000-failure log, a rerun that must hit the cache, a resume path. Launch only when all pass. |
| Baseline | Run the suite once at the start HEAD. Fix or mark xfail(strict) each failing test in its own commit, so exit 0 means green and no allowlist exists. |
| Monitors | Start the 8 GiB disk monitor and the pytest-temp cleaner before the first dispatch. Keep a registry of every background shell with its stop-when condition, at most 2 live monitors. |

### 2.2 Per task (all ready tasks in parallel)

| Step | Configuration |
|---|---|
| Design gate | One Sonnet agent per task, all tasks at once. Output: code map, test matrix, brief coverage list, no open decisions. One design pass per task. A Haiku `git diff since gated_at` check replaces re-gates. No second verification fleet. |
| Tests | Split each task's matrix across 3-4 Sonnet authors by file or group, each capped at 40 tool calls and 200K context. Paste only the relevant brief part (under 24 KB) into the prompt. |
| RED | One pytest call over the task's ids with `--junitxml`. A script classifies each id. Any failed cell means failing. Tests owned by unmerged tasks are UPSTREAM_PENDING, never a stop. The script refuses an empty selection. Budget 5 min. |
| Implement | Fan out by failure cluster or module, at least 3 implementers when a task has over 10 source files or 100 failing tests. Implementers run only their own test ids, never the full suite. |
| Typing | Run the commit hook's exact checks (ruff, then mypy on changed src and tests, `MYPYPATH=src`) in each copy, in parallel, as soon as its tests pass. Fix "source file found twice" with `importlib.import_module("tests.x")`. |
| Review | At most 2 rounds. Codex lenses run concurrently with the sharded suite. No separate refute pass: the fixer reproduces each finding first. Round 2 reviews only the fix diff. A brief-coverage check runs before the first commit. |
| Fix split | Split by failing test function, at most 150 failures per fixer, up to 16 fixers, each capped at 40 calls and 20 min. A watcher flags any agent at 100 turns or 20 min. |
| Cleanup | The task's last step removes its copy worktree once its SHA is on the phase branch. |

### 2.3 Integration

| Step | Configuration |
|---|---|
| Pre-merge | Pre-merge task N onto the commit immediately before it, in its own copy, for every task at least 2 places behind the merge head. The merge step blocks on that copy's done file and uses the same base. Dry-run pipe-apply on one task first. |
| Merge | One Sonnet agent per task: apply, resolve hunks with Edit, typed commit. The prompt carries inline the commit hook's checks and "leave docs checksums and sync_docs alone". 5-minute cap per task: on breach, split the conflict files across parallel agents. |
| Per-merge signal | After each commit, run that task's own test ids in the background, without blocking the next merge. |
| Docs | Run `doc-sha.py` once, just before the combined suite. |
| Combined gate | One sharded suite, then ruff, mypy, `sync_docs --check` and `git diff --check`. No per-task suites and no Codex reviews in integration. |
| Fix rounds | At most 2. Each round reruns only the previous round's failing tests (`PYTEST_RUN_FOCUS_FILE`), then exactly one full suite once those pass. |

### 2.4 Suite runner

- **Cache key:** HEAD plus the tracked diff, excluding `.rush/`, `docs/` and caches. Once a tag has a result it is DONE, and a rerun needs a new tag.
- **Logs:** one log per run, never overwriting a finished one. Failing ids are written to a file the moment the shards finish.
- **Shards:** 8, balanced on per-test times from the last green run. Two suites at a time at most.
- **Mass failures:** over 60 failures skips serial confirmation, and failures are grouped by test function.
- **ETA:** from the running shards' own progress, never from a baseline. No CPU-heavy probe while a gating suite runs.
- **Stale runs:** a suite run against a commit that has since been superseded exits on its own once the branch moves past that SHA.

### 2.5 Agent prompts (one shared preamble)

- **Token tools:** rtk filtered forms (`rtk grep/read/pytest`); `rtk proxy` only when output must be raw. graft before reading spans; `ctx_execute_file` for large files; one batched read in the first turn.
- **Temp files:** `--basetemp` inside a TemporaryDirectory; delete any temp HOME before reporting; reuse the shared `.venv`.
- **Imports:** snapshot or copy checks pass `-o pythonpath=<dir>/src` and print `rush.__file__` first.
- **No `.scratch`:** never write there, never touch another repo.
- **Launch check:** the launch script verifies the preamble is present in every dispatched prompt.

### 2.6 Run control

- **Stopping:** no TaskStop or kill on a workflow or agent without James's literal stop. Improvements apply only to work not yet started.
- **Background helpers:** every helper shell I start carries a stop-when condition and is removed the moment it is met. One-off searches run under `rtk proxy timeout 60`.
- **Relaunch, never resume:** never resume a parallel workflow to change prompts (the resume cache is positional). Relaunch fresh with args marking finished steps done, after a mock run lists the exact agent calls.
- **Workflow agents:** never SendMessage a workflow-owned agent, because it starts a second copy.
- **Classifier denials:** retry once with the narrowest equivalent action, then surface it.
- **Power:** before any run longer than 10 minutes, check `pmset -g batt`; on battery, say so and get AC first. `caffeinate -i` does not stop a low-battery sleep.
- **Wait loops:** every `until <marker>` loop runs under `rtk proxy timeout N`; no unbounded sleep loops.
- **Kill orders:** "kill unused shells/agents" means one OS-level sweep (`pgrep -fl` on the session id, scratchpad and worktree paths, plus ListAgents) and ending every idle one in that same turn. A wait loop can be ended by writing its marker.
- **"Finish now":** ship what is verified (commit, push, merge) in that turn; list what is not done in one line. Never answer with an ETA plan, a new agent or new tooling.
- **Cleanup before removal:** archive gate logs and records into `.git/phase<id>-archive/`, verify counts, then remove the worktree, without asking.

### 2.7 Reporting

- **First line:** the answer or the measured number, with its source.
- **Standing requests:** no "say go" for the next step of a request James already made. Ask only for pushes, history rewrites and scope changes.
- **Decisions:** no options tables and no open decisions; resolve from evidence.
- **Wording:** no apologies and no future-tense promises. Every "verified/done/started" claim cites the command or the dispatch id from that turn.
- **Problems:** a problem named in a reply is fixed in that same turn, or carries the one question that unblocks it.
- **Status:** a watcher posts each state change (commit, suite start, suite finish) unasked. One report per change.
