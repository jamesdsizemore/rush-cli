# Slop-Busting & Hallucination Defense

Large Language Models are incredible at generating text, but they have a few notorious quirks when writing code:

1. **The Empty Stub Trap**: The model generates a clean class header, but puts `# TODO: implement this later` or `pass` inside the body—leaving critical features hollow.
2. **The "Novel of Comments" Syndrome**: The model peppers every 2 lines of code with obvious, repetitive narration (`# Now we increment i by 1`).
3. **The Phantom Dependency**: The model imports a library that doesn't exist or was never installed in your `pyproject.toml` or `package.json`.
4. **The "I Swear I Tested It" Illusion**: The model claims your feature works, but never actually created or ran a test file.

Rush gives you dedicated, automated tools to bust AI slop and keep your codebase clean.

---

## 1. Catching AI Boilerplate with `rush slop`

```bash
rush slop .
```

`rush slop` runs deterministic AST heuristics that scan for patterns characteristic of low-quality or hallucinated AI outputs:

- **Excessive Comment-to-Code Ratios**: Flags files where conversational filler comments outweigh actual logic.
- **Hollow Stubs**: Detects functions with empty bodies, bare `pass` statements, or unresolved placeholder comments.
- **Duplicate Dictionary Keys & Object Properties**: Catches copy-paste hallucinations in large data structures.

---

## 2. Enforcing Test Existence with `rush tdd`

```bash
rush tdd .
```

When you are vibecoding fast, it is easy to forget to ask the model for tests. 

`rush tdd` automatically compares your modified source files against your test directories:
- If you touched `src/auth/jwt.py`, Rush verifies that `tests/test_jwt.py` (or `src/auth/jwt.spec.ts`) exists and tests the updated logic.
- If no test exists, Rush flags `[FAIL] Missing test contract for jwt.py`.

---

## 3. Detecting Phantom Imports with `rush dead` & `rush check`

```bash
rush dead .
rush check .
```

- Catches imports of packages not declared in your package manager lockfiles.
- Finds functions that were generated by the AI but never called anywhere in the project.

---

## The "Zero-Slop" Golden Rule

Add this one-liner to your prompt when working with any AI assistant:

> *"Always write production-ready code with complete implementations (no placeholder stubs), lean docstrings (no obvious inline comment narration), and verify that `rush check` and `rush tdd` pass."*
