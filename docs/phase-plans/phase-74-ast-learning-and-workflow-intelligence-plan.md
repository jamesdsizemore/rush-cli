## 3. Resolved data and API contracts

### 3.1 Symbol graph and change events

`SymbolRef = {project_id, worktree_id, revision, language, path, qualified_name, kind, span, source_sha256, structural_sha256, parser_id, parser_version}`. Path is project-relative after physical containment; span uses 1-based lines and byte offsets. Qualified name includes nesting and lexical scope (`pkg.mod.Class.method`, `src/widget.tsx::Panel.render`); duplicate names in different scopes never share an ID. `source_sha256` hashes exact declaration bytes; `structural_sha256` hashes a normalized parser subtree excluding trivia but retaining signatures, decorators, relevant constants and body structure. Structural equality suggests a move; it never transports a test pass. Format-only changes retain structural identity but exact hash/revision changes. Generated files carry generated status and generator/input references where known; absent input coverage is `unknown`.

One project/worktree index lives under authorized project `.rush/` state. Each file transaction records source hash, parser/grammar/schema versions, parse state, exported symbols and typed edges; replaces that file's previous nodes/edges atomically, including deletion. Index trigger is permitted explicit `graph_context`/index request, source-edit lifecycle event, or relevant public scan/review/verification operation; read-only queries never initialize or mutate it. Dirty working-tree content uses content digest and worktree identity in addition to Git revision. Two clean projects using one Rush install do not modify their manifests, lockfiles or virtual environments. Source changes, grammar/schema changes, config/toolchain changes and deleted files invalidate exactly dependent graph entries and derived memory; a missing/stale/partial index cannot assert currentness. Indexing has file/time/byte ceilings and reports skipped paths and coverage, not silent success.

Edges are typed `CONTAINS`, `IMPORTS`, `CALLS`, `REFERENCES`, `INHERITS`, `EXPORTS`, `TESTS`, `IMPLEMENTS_BEHAVIOR`, `AFFECTS_CHECK`, `DEPENDS_ON` with source and target refs, origin (`syntax`, `semantic`, `observed`, `user`), exact evidence/version and resolution state. Static direct local calls/imports resolve when unambiguous; external, reflection, decorators, inheritance overrides, generated dispatch and dynamic string routes remain candidate or unresolved until stronger evidence arrives. The graph must expose per-language/file coverage and unresolved-edge counts. An empty edge set does not mean no callers. No AST-derived edge may promote a user statement or serve as runtime verification.

### 3.2 Evidence, advice and action

Add typed `claim`, `hypothesis`, `experiment`, `pattern`, `workflow`, `skill_candidate`, `design_contract` and `architecture_contract` content through existing versioned store/relations, reusing existing subjects where valid. Each includes owner/scope, source refs, symbol/dependency/config/environment conditions, affirmative and contrary evidence, exceptions, created/current revision and lifecycle (`candidate`, `current`, `stale`, `unknown`, `rejected`, `superseded`). User-confirmed decision, user correction, agent proposal, inferred pattern, observation and test receipt retain distinct authority through recall, summary, compaction and export. A stated requirement needs the existing authorized statement resolver; repeated code style or screenshot never creates approval. Write uses existing grant and compare-and-swap; reads use A's shared defended retrieval and source/owner binding. When A's defensive operation is unavailable, affected automatic read is held and reported, never widened.

Expose one `MemoryTool` family of operations in `src/rush/tools/memory.py` with CLI/full-MCP parity: `graph_context` (bounded read/index status), `learning_next` (applicable advice, failed variants, competing hypotheses, proposed discriminating checks), `learning_observe` (receipt-linked action/outcome), `workflow_suggest`, `skill_candidate` (show/accept/edit/reject/export), and `project_contract` (current design/architecture with cited anchors). `operation`, `path`, `session_allowlist`, `project/worktree/revision`, `target` and request-specific fields are explicit; absence of authorized scope returns `E_PERMISSION`. Existing operations and result shapes remain compatible. Each read returns IDs/versions, inclusion reason, authority, applicable conditions, freshness, graph coverage, unresolved obligations and expansion handles; unknown/denied/disabled/parse-failed states are visible. Every event records producer, trigger, consumer, evidence used and actual receipt. A result merely shown to an agent is not proof it was followed.

`learning_next` chooses no action automatically. It orders candidate *permitted* experiments by ability to separate named hypotheses, required-check priority, cost and execution grant; predictions identify what each outcome would support or refute. A result changes a hypothesis only through an actual receipt linked to the same revision/conditions. Failed repair matching includes symptom, qualified symbol/structural fingerprint, dependency/config/environment and strategy—not patch hash alone. Same conditions warn against repeat; changed conditions permit retry with the difference shown. Similarity can suggest recipe adaptation but never apply a patch or assert success. Last-success comparison distinguishes code delta, dependency/config delta, engine unavailable and stale receipt. Required checks are unioned from applicable user intent, repo/project gates, tests and security/dependency/license observations; ranking may reorder but never remove required checks. Missing engine leaves `unverified` obligation.

For TC13, `src/rush/memory/learning_context.py::rank_advice` owns **all ordering of memory evidence**, including applicability, relevance, observed outcomes and immediate user-correction demotion. It emits a stable sequence of `RankRecord = {artifact_id, artifact_version, applicability_tier, failure_or_correction, score, evidence_receipts}` plus authority, freshness, scope and inclusion/exclusion reason. A score is an explainable within-tier ordering value, never a trust or permission value. Applicable explicit requirements and mandatory checks lead; current exact-symbol/exact-condition evidence follows; current caller/dependency evidence follows; weaker structural matches and inferred patterns follow. Directly linked correction/failed use removes inapplicable advice or demotes it within its condition tier immediately; verified helpful use may promote it only within that tier. New and contrary evidence retain a reserved slot so popularity cannot suppress them. Record delivered item, selected action, actual result, later expansion and correction cost; missing action link means `unattributed`, not positive feedback. Evaluate frozen held-out tasks against the same fixed relevance order before enabling outcome adjustment. Authority and visibility filters run before ranking. Phase 75's packet selector consumes this ordered memory stream and may budget/interleave it with **nonmemory** code/tool candidates; it cannot reorder memory items or restore excluded/harmful advice. Phase 75 owns utility learning only for nonmemory code/tool candidates and total packet allocation.

### 3.3 Workflow and skill lifecycle

Capture only consented, permission-visible task events from B's lifecycle receipts and existing invocation/verification paths. A task boundary contains goal, scope, environment, ordered steps, branch conditions, user interventions, exceptions, actual outcome and evidence IDs. Normalize volatile IDs for comparison while retaining source versions, branch conditions and grant requirements. Candidate induction compares at least two independent successful tasks with failure/cancelled/overridden counterexamples; repetition alone yields no recommendation. Matching uses task/conditions and an existing-helper/skill dedup check. Unknown outcome, missing capture or changed environment is visible; it cannot increment success evidence.

`workflow_suggest` returns applicable versioned procedure, rationale, positive/negative examples and expected reuse cost; agent may propose permitted steps only. `skill_candidate` drafts name, project/personal scope, inputs, applicability, ordered/conditional steps, user judgment points, checks, exceptions, stop conditions and evidence links. Suggestion, acceptance, edit, rejection, canonical version and host-specific export are separate states. Rejected equivalent suggestion is deduplicated until a material new condition or explicit user reversal; an explicit user creation request authorizes creating the draft/skill without redundant confirmation. Export is a preview/explicit user-controlled write through supported host packaging; no silent install, privilege grant or executable generated code. Existing `AgentSkillGenerator` may format a trusted accepted export but is not the induction engine. Later uses attach real outcomes to the exact version; failures/corrections narrow applicability and revalidate changed dependencies. Only the relevant short fragment enters context; full procedure stays available by handle.

### 3.4 UI and architecture contracts

`design_contract` stores exact user-selected reference IDs/digests, approved tokens, current component/symbol anchors, typography/color/interaction/responsive/accessibility rules, surface exceptions and rejected directions. `architecture_contract` stores explicit decision/ADR text and rationale/alternatives separately from a revisable inferred model of current modules, seams and graph edges. User-approved rules remain authoritative within host instruction hierarchy; inferred convention is advice. Views label “user chose” versus “inferred from current code.” Acceptance requires real rendered desktop/mobile UI and actual component/token inspection; AST alone cannot verify visual compliance.

### 3.6 Graph transaction, migration and dependency algorithms

Proposed `index.py::index_paths(root, *, paths, access, expected_subject, limits) -> IndexReceipt` obtains Phase 72 containment/visibility and Phase 73 resolved policy, detects language by declared extension (`.py,.ts,.tsx,.rs`), rejects symlink escapes and reads bounded exact bytes. Python `ast` and actual tree-sitter TS/TSX/Rust grammars enumerate every named declaration, lexical containment and source ranges. Python byte columns are UTF-8 byte offsets; tree-sitter byte ranges likewise. Canonical qualified name contains module-relative path and full lexical owner; overload/repeated declarations append declaration ordinal. Node ID hashes project/worktree/language/path/qualified-name/kind/ordinal, while each snapshot binds revision/dirty digest. Resolve direct identifiers by lexical scope before imports; resolve imports/exports by contained module paths, never simple-name global joining. `self.method` uses containing class when unique; ambiguous aliases, overloads, reflection, macro expansion and dynamic dispatch remain unresolved edges. Rust `impl`/trait owner identity and TSX arrow components are parsed node kinds. Syntax error replaces the file's current generation with `parse_failed`, preserving previous immutable snapshot only as stale inspection; do not leave old nodes current.

Proposed `CodeGraphStore.replace_file_snapshot(file_snapshot, nodes, edges, *, expected_generation)` uses `BEGIN IMMEDIATE`, validates expected generation/source digest, removes current file-owned outgoing edges and nodes, inserts complete replacement, moves incoming obsolete target references to unresolved metadata with `target_id=NULL` and preserved prior-ref/reason (never dangling compatibility edge), updates coverage and generation, and commits once. Delete is replacement with tombstone; rename is delete+new snapshot in one transaction when both are one event. Cross-file inbound edges resolve only to current refs. Concurrent stale writer returns `E_VERSION`; busy returns `E_STORE_BUSY` without partial rows. Reader sees old or new complete generation, never partial replacement. Source changes during parse return `E_STALE_SOURCE`; no publish of stale AST.

Graph schema v2 retains legacy `GraphNode` columns and methods as a compatibility projection, adds qualified identity/source/version/coverage in snapshot tables, and adds edge origin/resolution/evidence metadata. `find_nodes_by_symbol` remains a list; new qualified lookup requires full ref and fails ambiguous lookup rather than taking first row. Legacy simple-name traversals remain candidate-only with coverage, never impact proof. v1 detection is read-only; reports `migration_required`. First granted explicit index takes SQLite backup of graph only, rebuilds v2 in adjacent Rush-owned file, integrity-checks it and atomically replaces index with generation CAS; retains recoverable v1 backup. Crash before replace leaves old index; crash after replace leaves complete v2. Failed integrity/ABI/disk-full leaves old bytes and exact error. Memory DB remains untouched by graph rebuild. Old memory refs become stale/unknown rather than being silently rebound. Reopening current binaries against v2 and rollback against retained v1 have explicit tests. Rebuild happens on parser/schema-version change; no in-place assumption of compatible trees.

Proposed `code_dependencies.py::invalidate_derived(root, change_refs, *, access, expected_versions) -> InvalidationReceipt` traverses reverse typed `DEPENDS_ON/AFFECTS_CHECK/IMPLEMENTS_BEHAVIOR` edges with visited IDs; direct changed/deleted nodes seed queue. Each artifact stores complete dependency refs plus `dependency_coverage=complete|partial|unknown`. Matching hash/parser/config/environment dependencies retain current structural analysis, never reuse nondeterministic runtime pass. Affected refs CAS to stale and keep exact prior versions/reasons. Partial/unknown dependency coverage conservatively sets dependent advice unknown; unrelated complete deps remain current. Cycles terminate. Because graph and memory use separate DBs, graph commit includes `pending_invalidations(event_id,generation,change_refs,applied=false)` with unique event ID in the same transaction. Consumer query compares artifact dependency generation to current graph and holds affected/unvalidated advice immediately, even if memory mutation failed. Canonical memory event/receipt records idempotent CAS transitions; graph event marks applied only after canonical memory receipt. Resume repeats unapplied transitions only; crash recovery never exposes old current advice. Structural candidate migration requires unique fingerprint plus enclosing/import evidence; ambiguity returns candidates without transfer of approval/pass.

V2 schema file map is `src/rush/codegraph/store.py`, not a new migration framework: `file_snapshots` key `(project_id,worktree_id,path,generation)` with source/parser/schema/status/coverage JSON; `symbol_snapshots` key `(node_id,generation)` with qualified ref/span/hash/content and foreign key to file snapshot; `edge_snapshots` key `(edge_id,generation)` with origin/resolution/evidence and nullable unresolved target; `current_files` maps canonical path to current generation; `pending_invalidations` as above. Index current qualified name/path and reverse target/ref dependencies. Legacy `nodes/edges` project current resolved snapshots only, retaining seven-column GraphNode and existing API. Historical snapshots remain inspection-only. Migration/rebuild uses SQLite backup API so committed WAL state is included; physical main-file copy is insufficient. API/schema/parser version drift always rechecks installed grammar probe. Official [Parser 0.26 API](https://tree-sitter.github.io/py-tree-sitter/classes/tree_sitter.Parser.html) and [Language ABI metadata](https://tree-sitter.github.io/py-tree-sitter/classes/tree_sitter.Language.html) were checked 2026-10-04: parse bytes with Language/Parser, inspect grammar ABI, treat timeout/None as failed coverage and reset parser before a different file. These sources establish interface, not actual four-language installed acceptance.
