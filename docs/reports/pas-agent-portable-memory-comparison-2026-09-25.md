# PAS-Agent portable memory: implementation and implications for Rush

Research date: 2026-09-25. PAS source pinned to [`0c9515a6ec9bb32c3f33a93b3f981e283d211abd`](https://github.com/gfirik/pas-agent/tree/0c9515a6ec9bb32c3f33a93b3f981e283d211abd). Read-only source and test inspection; no installation, executable testing or real-host acceptance performed. Rush comparison uses current implementation evidence in the [memory review](memory-system-implementation-review-2026-09-25.md) and proposed [Phases 72–75](../phase-plans/memory-program-contract.md). Proposed Rush capability is not presented as shipped.

## What PAS actually makes portable

PAS provides **portable task state**, rather than transferring a provider's private conversation, model state or context window. Its implemented path is: explicit CLI updates → local structured session → Markdown export → another agent reads that file. This directly addresses switching agents without reconstructing task progress. The project labels itself alpha; automatic hooks and AI summarization remain roadmap items. [Project description and commands](https://github.com/gfirik/pas-agent/blob/0c9515a6ec9bb32c3f33a93b3f981e283d211abd/README.md).

The provider-neutral record lives at `.pas-agent/session.json`. Schema version 1 contains session identity/timestamps, task description/objective, completed and remaining work, next action, decisions, blockers, constraints, discoveries, Git state and checkpoints. Checkpoints snapshot task state and changed-file metadata; these are not source-code backups or proof that recorded work passed checks. [Session model](https://github.com/gfirik/pas-agent/blob/0c9515a6ec9bb32c3f33a93b3f981e283d211abd/crates/pas-agent-core/src/session.rs#L5-L65).

Initialization chooses the Git root; later commands find an ancestor session. Storage checks schema compatibility and writes a sibling temporary file, flushes it and renames it over the destination. This protects against truncated writes; it does not by itself merge concurrent agents' updates. Cross-machine transfer uses the user's file/Git transport, not a PAS sync service. [Storage implementation](https://github.com/gfirik/pas-agent/blob/0c9515a6ec9bb32c3f33a93b3f981e283d211abd/crates/pas-agent-core/src/storage.rs).

`update` changes structured fields; `checkpoint` records supplied progress plus current Git observations. `export` refreshes Git metadata, saves the session and writes the target instruction file. It neither launches the destination host nor proves that host consumed the record. These commands do not ingest agent transcripts, infer preferences or learn workflows. [CLI command surface and export](https://github.com/gfirik/pas-agent/blob/0c9515a6ec9bb32c3f33a93b3f981e283d211abd/crates/pas-agent-cli/src/main.rs#L27-L127), [export implementation](https://github.com/gfirik/pas-agent/blob/0c9515a6ec9bb32c3f33a93b3f981e283d211abd/crates/pas-agent-cli/src/main.rs#L412-L440), [Git capture](https://github.com/gfirik/pas-agent/blob/0c9515a6ec9bb32c3f33a93b3f981e283d211abd/crates/pas-agent-core/src/git.rs#L8-L55).

## How it crosses agent boundaries

Seven target names map to three instruction-file conventions: Claude uses `CLAUDE.md`; Gemini uses `GEMINI.md`; Codex, OpenCode, Cursor, Kiro and Antigravity use `AGENTS.md`. Export inserts/replaces a marked section, normally preserving surrounding user text. `--force` deliberately replaces the whole file. The serializer limits recent checkpoints to 10 and changed files to 50, but those item limits are not a tokenizer-aware bound on the complete document. [Target mapping and renderer](https://github.com/gfirik/pas-agent/blob/0c9515a6ec9bb32c3f33a93b3f981e283d211abd/crates/pas-agent-core/src/context.rs#L7-L48), [managed export](https://github.com/gfirik/pas-agent/blob/0c9515a6ec9bb32c3f33a93b3f981e283d211abd/crates/pas-agent-core/src/context.rs#L222-L268).

This is a useful low-dependency interoperability mechanism. It relies on the receiving host's instruction-loading behavior and the agent running update commands. Exporting before a new session is its documented route; an already running agent needs an explicit reread or restart. Supported filename mapping alone is not evidence of active memory in every host/version. [Usage contract](https://github.com/gfirik/pas-agent/blob/0c9515a6ec9bb32c3f33a93b3f981e283d211abd/README.md#L202-L241).

The renderer labels the content as another developer/agent's progress record and gives project instructions precedence. It neutralizes structural Markdown injection through headings/comments. This does not establish semantic trust in statements such as “all tests passed.” Inspection also found `trim_end` on surrounding content: its preservation behavior is not strictly byte-identical. Local CLI tests cover file export, mappings and temporary Git projects; they do not establish real receiving-agent use. [Renderer and tests](https://github.com/gfirik/pas-agent/blob/0c9515a6ec9bb32c3f33a93b3f981e283d211abd/crates/pas-agent-core/src/context.rs), [CLI tests](https://github.com/gfirik/pas-agent/blob/0c9515a6ec9bb32c3f33a93b3f981e283d211abd/crates/pas-agent-cli/tests/cli.rs).

## Comparison with Rush

| Dimension | PAS at inspected revision | Rush current evidence and planned response |
|---|---|---|
| Canonical state | One editable structured task/session file | Existing typed artifacts, versions, relations and retrieval. Phase 72 fixes authority, freshness, retrieval and user control; no replacement session database. |
| Activation and continuation | Explicit CLI updates and instruction-file export | Current audit found configured MCP without model-visible use. Phase 73 specifies native hooks, bootstrap, ongoing capture, task discovery and independently evidenced receiver continuation. |
| Meaning and learning | User/agent-authored progress and decisions | Phase 74 adds evidence-grounded patterns, failed approaches, workflows, skill candidates, design/architecture intent and attributable agent improvement. These are implementation obligations, not current superiority claims. |
| Code grounding | Git identity and changed-file metadata | Phase 74 requires qualified AST identities, current relationships, source-linked invalidation and honest unknown coverage. Git status alone cannot deliver that. |
| Context economics | A concise export with checkpoint/file count limits | Phase 75 requires whole-packet budgets, selective recovery, typed joins, deltas, actual usage/cost and measured reuse break-even. No measured PAS-versus-Rush token-saving result exists here. |

Rush's evidence for these distinctions is the [implementation audit](memory-system-implementation-review-2026-09-25.md), [activation plan](../phase-plans/phase-73-agent-activation-and-continuity-plan.md), [learning plan](../phase-plans/phase-74-ast-learning-and-workflow-intelligence-plan.md), and [efficiency plan](../phase-plans/phase-75-context-and-token-efficiency-plan.md). PAS has a narrower, understandable continuation route already represented in code. Rush's richer specification does not compensate for an agent failing to discover or use it.

## Useful influence: four concrete proposals

These are new proposals from this research, not approved changes to the frozen plans or a fifth phase. They retain every existing memory requirement.

1. **A portable continuation capsule, generated from canonical memory.** Extend Phase 73 T05 with a versioned export containing task/next action, explicit constraints, decisions, failed approaches, unresolved obligations, source/worktree identity and selected evidence. It must be a materialized snapshot of canonical artifacts, not another authority store. Include required evidence bodies for genuinely offline use; machine-local handles alone are not portable. Separate private/local references from self-contained records. Validate imported identity/schema/hash/freshness, retain original provenance and label unverifiable claims. Never export grants, capability tokens or credentials. Test offline receipt on another checkout/machine, stale source and changed paths.

2. **A minimal instruction-file bridge when native activation is unavailable.** Preserve the primary MCP/native route. A small managed block can name Rush, explain bootstrap and point to an approved capsule. Expose whether the receiver used live Rush or an offline snapshot. Keep user bytes outside the block identical, handle malformed/duplicate markers explicitly, and require reread acknowledgement for an existing session. This makes the current adoption failure recoverable without pretending the MCP tool became visible. Phase 73 T03/T05 is the natural owner; Phase 75 supplies the budget.

3. **One visible continuation journey.** Make task start → checkpoint → continue understandable from CLI and app views, backed by Phase 73's actual scope/receipt state. Show task, last verified progress, unresolved work and next action without requiring users to understand subjects, allowlists or transport internals. Agent hooks keep it current; explicit commands provide inspection and recovery. Measure successful continuation by another agent without the user restating history, including an interrupted sender and a missing native adapter.

4. **Portable-format conformance, including a possible PAS importer/exporter.** Reuse versioned canonical serialization and Phase 73/75 acceptance instead of adopting a second memory engine. An optional PAS adapter can map task fields to typed, unverified imported artifacts, preserving constraints and contradictions without promoting assertions to verified truth. Test round-trip meaning, unknown versions, Unicode, concurrent updates, redaction, marker preservation and receiver use. Assess demand before adding the interoperability adapter; the capsule and activation lessons do not require PAS as a dependency.

## Decision

Borrow PAS's small, inspectable continuation contract and direct user journey. Keep Rush's canonical authority, source grounding, dynamic learning and measured context control. Do not copy an ever-growing session into permanent instructions, mistake filename compatibility for host activation, or mark imported progress as verified. The useful design question is whether a fresh agent can start with a compact, comprehensible task state and retrieve trustworthy evidence immediately; Phases 72–75 must prove that outcome through their existing acceptance lanes.

Research limits: no PAS binary/tests were run, no real-host continuation or measured comparative token trial was performed, and portability across machines was inspected as a documented file/Git workflow. Repository source was pinned; upstream may change after this review.
