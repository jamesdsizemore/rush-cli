### X2 [critical] A naive Pydantic union schema is incompatible with the hosts
- **Proven locally:** `TypeAdapter(Annotated[A|B, Field(discriminator="operation")]).json_schema()` has top-level keys `['$defs','discriminator','oneOf']` and no `"type":"object"`.
- **Proven locally:** none of the 79 schemas currently published has a top-level `oneOf/anyOf/allOf`. Nested `anyOf` and `$defs` are already published (e.g. `rush_memory.subject`, `project_id`) and existing Claude/Codex registrations use them.
- **Not provable locally (needs an authenticated real-host call):** the Anthropic Messages API rejects `input_schema` with top-level oneOf/anyOf/allOf. The string is not in the `claude` 2.1.283 client binary (searched), so the check is server-side.

### X3 [critical] `Literal[1]` accepts `True` and `1.0` even with `strict=True`
- **Proven** with pydantic 2.13.4: `{'schema_version': True}` and `1.0` both validate to `1`.
- `Annotated[StrictInt, Field(ge=1, le=1)]` rejects both with `int_type` (proven).
- **Resolution:** every schema_version field uses `Annotated[StrictInt, Field(ge=1, le=1)]`. All booleans use `StrictBool`. All integers use `StrictInt` with bounds.

### X4 [major] SQLite `mode=ro` on a WAL database creates `-shm`/`-wal` sidecar files and leaves them after close
- **Proven:** on a WAL DB at rest, `file:t.db?mode=ro` produced `['t.db','t.db-shm','t.db-wal']` that persisted after close.
- `immutable=1` with no sidecars creates nothing. With an active writer, `immutable=1` misses uncheckpointed rows (proven: saw 1, not 2).
- Both relevant DBs are WAL:
  - `memory.db`: `memory/store.py:406`.
  - `mutation_ledger.db`: `dashboard/state.py:533-534`.
- `TypedArtifactStore.open_readonly` (`memory/store.py:1439-1458`) therefore breaks its own "never creates ... journal" docstring on WAL DBs.
- **Resolution: zero-write read-only open algorithm**, used for the ledger (T23, in `dashboard/state.py`) and required of T20's `open_readonly` (memory count consumed by T23):
  1. DB missing → `absent`.
  2. `<db>-wal` exists → open `?mode=ro`. No new file is created because the sidecars already exist; if `-wal` exists but `-shm` does not, use step 3.
  3. Otherwise open `?mode=ro&immutable=1`, read, then re-`lstat` the DB. If `(st_size, st_mtime_ns)` changed or `-wal` appeared, discard the result and redo step 2 once.
  4. `sqlite3.DatabaseError` → `corrupt`.

  Test: a before/after directory snapshot (names, sizes, `mtime_ns`, sha256) is identical.

### 3. Design
**Selection**
- CLI: `status_cmd(path=None|Path)`.
  - PATH given → `select_logical_target(str(path), anchor=Path(os.getcwd()))` (lexical cwd, no `.resolve()`, per 5.4).
  - No PATH and `--session` → `_load_session_selections` via a strict reader (missing file = unbound; corrupt = error).
  - Otherwise walk the cwd.
- MCP: omission is detected through `context.original_requested_targets == ()`, after fix (a).
- Registered match: strict registry read, then `entry["root"] == str(canonical logical_root)`. Do not call `resolve_project` for "is it registered?", because it raises and masks corruption.

**Strict registry reader**
- `lstat(<data_root>/projects.json)`:
  - absent → `missing`.
  - `OSError`/`IsADirectoryError` on read → `unreadable`.
  - JSON error or wrong shape (`projects` not a dict) → `corrupt` with sha256.
  - otherwise `ok`.
- Never creates `data_root`.

**Chronology selector** (projects.py, read-only, no `project_run` mutation code)
1. `runs_dir = root/.rush/runs`. Absent → `no_run`. Iterate `lstat` dirs; a symlinked run or attempt dir is corrupt evidence.
2. Per attempt dir, load `attempt.json` strictly:
   - dict;
   - `run_id == run dir name`;
   - `attempt_id == attempt dir name`;
   - `project_id == registered project_id`;
   - `attempt_generation` is `int`, not `bool`, and `> 0`;
   - `started_at` parses with `datetime.fromisoformat`, has `utcoffset()==0`.
3. Within a run: generation-bearing attempts outrank legacy (no-generation) attempts, matching P69-02k (`project_run.py:1312-1336`). Duplicate generation → that run is `chronology_ambiguous`. A run whose attempts are all legacy is resolved only if it has exactly one attempt.
4. Across runs: the latest is the run whose selected attempt has the max `started_at`, labeled `ordering:"started_at_utc"`.
   - Equal max timestamps → `chronology_ambiguous` with affected IDs.
   - Any run with unresolvable ordering evidence → `latest_unresolved` with its IDs; never fall back to an older success.
   - Never sort UUIDs. Never compare generations across runs. Never use manifest `created_at` for start order.
5. Completion: `manifest.json` present → `completed` (its `run_state`/aggregate); absent → `incomplete`.
6. Ledger (X4 open of `<data_root>/dashboard/mutation_ledger.db`):
   - `SELECT published_generation, latest_published_run_id, latest_published_attempt_id FROM project_generations WHERE project_id=?`.
   - `SELECT run_id, attempt_id, operation_id, owner_instance_id, plan_id FROM scan_admission WHERE project_id=?`.
   - Use `PRAGMA table_info` for the migrated `attempt_id` column; a missing column is `null`; a missing table is "no evidence".
   - Never read or interpret `project_generations.value`.
   - An admission row makes its attempt the current attempt, with activity from `observe_owner_lock`.
7. `observe_owner_lock`:
   - POSIX: path `<data_root>/owners/<id>.lock` without mkdir; `lstat` absent → `activity_unverified`; else `os.open(O_RDONLY)`; `flock(LOCK_SH|LOCK_NB)` fails → `running`; succeeds → unlock/close → `not_running`.
   - Windows: `OpenMutexW(SYNCHRONIZE, False, name)` (never `CreateMutexW`); NULL → `activity_unverified`; `WaitForSingleObject(h,0)` TIMEOUT → `running`; acquired → `ReleaseMutex` + close → `not_running`.
8. Stale:
   - The selected completed attempt header needs `source_signature_format == PROVENANCE_FORMAT`.
   - Compare its `source_signature` with `project_run._source_signature(root)` (1738-1768, read-only rglob/stat; lazy import as projects.py:771 does).
   - Missing → `unverifiable`.

**Agents**
- `discover_agents(home, rush_binary=ref)` (read-only, 453-525).
- `ref` = `resolve_rush_binary()` inside `try` (it refuses `.venv`/checkout binaries, 181-189). On failure: `binary_reference:{state:"unavailable",reason}` and no misconfigured comparison.
- Output only `command`/`args` of the Rush entry, passed through `sanitize_value`. Never `env` or other config content.
- Activation: `json.loads` of `agent_memory_store_path(...)` with an existence check (X5).

### 3. Design
**Class**
```python
class RushFastMCP(FastMCP):
    async def list_tools(self):
        tools = await super().list_tools()
        for t in tools:
            if t.name in REQUEST_MODEL_TOOLS:   # rush_project, rush_scan, rush_memory
                t.inputSchema = published_schema(t.name)
        return tools

    async def call_tool(self, name, arguments):
        if name in REQUEST_MODEL_TOOLS:
            outcome = validate_and_normalize(name, arguments or {})
            if outcome.rejected:
                return CallToolResult(content=[TextContent(type="text", text=json.dumps(env))],
                                      structuredContent=env, isError=False)
            arguments = outcome.arguments        # {"request": envelope} or validated flat args
        return await super().call_tool(name, arguments)
```
**Proven:** `_setup_handlers` registers `self.list_tools`/`self.call_tool` as bound methods, so the overrides take effect (`fastmcp/server.py:302-308`). The lowlevel server returns a `CallToolResult` as-is without output validation (`lowlevel/server.py:546`). No `_tool_manager` mutation.

**Validation order** (`validate_and_normalize`)
1. Container-string decode (behavior 8).
2. Form detection: `"request" in args` → legacy; else named.
   - Legacy form must have exactly `{"request"}` (anything else = mixed → reject `loc:[<key>]`).
   - Named form must not contain `request`.
3. TypeAdapter:
   - project/scan named: `Annotated[Union[...], Field(discriminator="operation")]`.
   - Legacy: the same union with required `schema_version`.
   - memory: callable `Discriminator(lambda v: v.get("operation","ask") if isinstance(v, dict) else getattr(v,"operation","ask"))` with `Tag`s. This preserves the `"ask"` default (`memory.py:287`).
4. `model_dump(exclude_unset=True)`.
5. Build the envelope:
   - project/scan → `{"request": {"schema_version":1, "operation":op, **fields}}`.
   - memory → flat dict.
6. `super().call_tool`. The T8 custom wrapper then anchors `request.project`/`path`/`parent` against the server-start cwd (`tool_registry.py:217-225`), identically for both forms.

**Flattening (`published_schema`)**
- From the same models: union of branch properties.
- If a field's schema differs across branches → nested `anyOf` of the distinct shapes.
- `operation.enum` = all operations.
- Required-where text is generated from each branch's required set.
- `request` property = legacy union schema (nested `oneOf` + `$defs`).
- Hoist all `$defs` to the top level (FastMCP already emits top-level `$defs` for memory).

## T3 — Consent-aware instructions and disconnect

### 1. Required behavior (testable)
1. `rush agent connect HOST --session S --project P` plans a Rush instruction block:

3. Consent:
   - Interactive TTY without `--json` asks `[y/N]`; only y/yes applies; EOF/Ctrl-C declines.
   - Non-TTY applies only with `--install-guidance` plus `--allow-cache-write --allow-artifact-write`.
   - Default is no write, reported as `guidance: pending|declined`.
   - Memory `--consent`, artifact grants and `--acknowledge` alone never imply guidance consent.
4. Markers:
   - `<!-- rush:begin v=1 hosts=<sorted,comma> sha256=<body digest> -->` … `<!-- rush:end -->`.
   - Exactly zero or one begin/end pair per physical file, in order.
   - Duplicate, nested or unmatched markers → conflict, no write.
5. A user-edited block (body digest ≠ marker digest) → conflict, left as is.
6. CAS: the preview records sha256 of the whole file (or absent). Apply re-reads it immediately before `os.replace`; a mismatch → conflict, no write.

   - MCP entry;
   - instruction block (or removes HOST from `hosts=`);
   - skill/hook resources;
   - hook activation.

   Changed components → `conflict` with path and digests. Running it twice → second run is a no-op `ok`.
8. Rollback on partial failure uses captured original bytes, restoring only while current digest == this transaction's written digest. Otherwise `recovery_required{component, path, expected, actual}`. A prior working registration survives.
9. Already-connected agents: InstallTool's early-continue branch (`install.py:479-488`) still runs guidance/asset reconciliation (preview; writes only with guidance consent). Reconnect is never required.
