**3. Design**
- **Root:** logical root = T8 `resolve_logical_root(Path(os.path.abspath(path or cwd)))` (read-only walk, `invocation/targets.py`). The registered match compares `_canonical_root(logical_root)` with strict-registry entry roots. `_canonical_root` does a read-only `resolve()`, which matches T8's registered-root authority. Two registered roots that both match (nested) → `AmbiguousRootError` with both IDs, returned as status `error`.
- **Readers:** registry (X5), descriptor, config (`rush.toml` via `load_config` in try/except, giving `missing|valid|invalid|unreadable` plus a diagnostic and SHA-256), engines (T15 inventory, `probe=False`), ledger view (X2), attempts (below), agents (`discover_agents` is read-only: it reads config files, `agents.py:453-525`, plus the strict agent-memory reader), and memory (T20 read-only useful count via X2).
- **Chronology algorithm:**
  - Walk `.rush/runs/*/attempts/*`, skipping symlinked directories and reading with lstat.
  - A header is valid only if it is a dict, `run_id == run dir name`, `attempt_id == attempt dir name`, `project_id == registered id`, `attempt_generation` is an int (not bool) greater than 0, and `started_at` is ISO-8601 with `utcoffset()==0`.
  - Within one run, order by generation; an equal generation means `chronology_ambiguous`.
  - Across runs, take the maximum `started_at` and set `ordering="started_at"`. A tie across different runs means `chronology_ambiguous` with every tied ID listed.
  - Any missing or corrupt header or terminal manifest means `latest_unresolved` with `affected_ids`, and an older success is never substituted.
  - Never sort UUIDs, never compare generations across runs, and never use the manifest's `created_at` for ordering.
  - Ledger admission, if present, identifies the current attempt, and its owner is observed via `observe_owner`. `project_generations.published_*` identifies the published result. `value` is never read.
  - Published `stale=true` if a validated attempt started after the published attempt, or if `source_changed=true` because `project_run._source_signature(root)` (read-only, `:1738`) differs from the published attempt header's `source_signature` with the same `source_signature_format`.
- **Envelope `raw` (schema_version 1):** `selection{source,requested_path,original_input,observed_root,logical_root,session_id}`, `registry{state,path,error}`, `project{registration,project_id,name,root,revision,configured,root_exists}`, `config{state,path,sha256,diagnostic}`, `engines{state,items[{engine_id,required,disposition,executable,version,version_source,reason,setup_action}]}`, `activity{state:idle|running|owner_dead|activity_unverified|unavailable, admission}`, `published{state,run_id,attempt_id,generation,run_state,finding_count,stale,source_changed}`, `latest_attempt{state:none|resolved|incomplete|latest_unresolved|chronology_ambiguous, run_id,attempt_id,started_at,attempt_generation,ordering,affected_ids}`, `agents[{agent_id,state,config_path,acknowledged_at,restart_required,capability_verified:false}]`, `memory{state,useful_count,reason}`, `next_actions[{reason,command}]`. Metadata scope: `kind=operation`, `file_count=null`, `reason=not_file_analysis` (T16).
- **Status:**
  - `error`: corrupt or unreadable registry, ledger, memory DB, or selection file; ambiguous root.
  - `warn`: unregistered or unconfigured project, missing required engine, unresolved or ambiguous chronology, `activity_unverified`, `owner_dead`, or stale published result.
  - `ok`: otherwise.
  - "No run" is informational. The summary never says "clean" or "passed".
- **Human render:** a T27 `status` family. Section order: Project, Config, Engines, Activity/Current, Published result, Agents, Memory, then Next actions with exact commands, shell-quoted.
- **No config gate:** the handwritten `status` command must not go through `_run_tool`'s `load_config` abort (`cli_support/rendering.py:110-114`). It builds the invocation through `resolve_invocation(config=None)` plus `InvocationExecutor` and renders with `exit_with_result`.
- **Executor observations:** the executor observation guard (`invocation/executor.py:472-476`) must also skip `operation_id=="status"` so a `[tools.memory] record=true` config plus a grant can never write.
