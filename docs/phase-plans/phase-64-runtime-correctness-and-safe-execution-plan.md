## 2. Decisions and invariant contracts

| Concern | Compared alternatives | Decision and tradeoff |
|---|---|---|
| Restoration | Whole-checkout reset; new rollback service; existing snapshot/patch primitives | Existing bounded snapshot/isolated-worktree primitives. More exact bookkeeping, but preserves user bytes/index and avoids another recovery subsystem |
| Trust boundaries | Guards in each transport; shared invocation/containment helpers | Shared implementation guard, with CLI/MCP tests. Every caller inherits the remedy |
| Result truth | Reclassify absent work as success; canonical aggregation | Preserve child results and nonexecution reasons; missing/failed work can make a run incomplete |
| Parsing | Broad regex; existing AST/parser dependencies; new services | Existing Python AST, SPDX parser, safe XML and explicit token parsing. No new service; lexical language parsing must prove comments/strings/multiline cases |
| Verification | Shape tests/version probes; actual target execution | Domain fixtures plus installed-engine execution. Version is provenance, never workload evidence |

Canonical ToolResult remains tool, engine/version, status, duration, summary, findings, with existing metadata extension points. Partial or absent evidence is explicitly identified; no placeholder metric substitutes. Permission checks occur before launch/write/network. A test may replace the subprocess boundary to verify argv and denial, but that does not satisfy the separate real-engine acceptance. Synthetic secrets must never appear in returned values or logs.
