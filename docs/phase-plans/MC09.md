# MC09 — Rank checks without dropping required verification

Implements `plan_checks()` in `src/rush/memory/verification.py` and the `plan_checks`
operation in `src/rush/tools/memory.py` (MemoryTool). Read-only: ranks a caller's
`required_checks` by real, already-recorded evidence (`TypedArtifactStore` episodic
observations written through the existing `write_observation()` from `experience.py` --
never a parallel store) and never drops or adds required membership, only reorders.

## Evidence ranks (lower sorts first)

| Rank | Evidence | Source |
|---|---|---|
| 0 | Observed regression (a `tests_contracts` observation with `status in {"fail","error"}` naming this check against a changed target) or a version-bound security/dependency/license finding reopened by a dependency version change | R12, R14, R16 |
| 1 | Measured coverage (a `tests_contracts` observation that actually executed against a changed target) | R12, R14 |
| 2 | Structural relation only (a `source_graph` observation -- e.g. blast-radius/api-diff -- naming this check; a graph heuristic, never promoted to rank 1) | R12, R15 |
| 3 | Configured-only (no evidence at all) | R12 |

Ties break on measured duration (`duration_seconds`, missing sorts last), then original
configured position (index in the caller's `required_checks` list).

A surviving mutation observation (`operation_id == "mutation"` with
`metadata.killed is False`) and a structural relation naming no required check (an
unmeasured dynamic consumer) are never invented as coverage -- both surface only as an
explicit `coverage_gaps` entry, never a rank boost.

Duplicate required checks sharing the exact same `(argv, cwd, environment)` identity are
merged into one run entry (`ids` lists every merged check ID); `required_ids` (computed
independently from the raw input list) always retains every original ID exactly once,
regardless of merging or ranking.

## Test fixtures, actual order, and first-detection timing

All 8 tests in `tests/test_memory_check_plan.py` pass (`18 passed` together with
`tests/test_memory_observations.py`; `1759 passed, 5 skipped` for the full suite).

- **`test_past_payload_regression_prioritizes_contract_check`**: required checks
  configured as `[slow-general, payload-contract, checkout]` (payload-contract at
  configured position 1 of 3). A prior `tests_contracts` observation records
  `payload-contract` failing against target `payload.user_id`. Actual plan order:
  `payload-contract` (rank 0) first, then `slow-general`/`checkout` (rank 3, tie-broken by
  original position). First-detection timing: the regression-linked check now runs at
  position 0 instead of its configured position 1 -- one slot earlier, and strictly first
  regardless of how many unrelated required checks exist. All 3 required IDs retained
  exactly once (`required_ids == [slow-general, payload-contract, checkout]`).
- **`test_required_checks_remain_after_early_pass`**: `checkout` has a prior *passing*
  `tests_contracts` observation against the same target that changed. `checkout` is
  promoted to rank 1 (measured coverage) but is never removed -- both `checkout` and
  `slow-general` remain in `required_ids` and `checks`.
- **`test_dynamic_consumer_gap_is_explicit`**: a `source_graph` observation names target
  `payload.user_id` with no `check_id`. `checkout` (the only required check) has no
  matching evidence and stays rank 3. The unmeasured relation surfaces as one
  `coverage_gaps` entry (`check_id: null`), never as invented coverage for `checkout`.
- **`test_missing_engine_keeps_required_check_unresolved`**: `e2e-browser` declares
  `engine: playwright`; `environment.available_engines == [pytest]`. `e2e-browser` stays in
  `required_ids` and `checks` (2 of 2), `availability: "unresolved"`, reason names the
  missing engine -- never silently skipped from the plan.
- **`test_security_license_version_change_reopens_finding`**: a prior
  `security_dependency` observation records `left-pad@1.0.0` as resolved by
  `dependency-audit`; the caller declares `left-pad` changed to `2.0.0`. `dependency-audit`
  jumps to rank 0 with a "reopened" reason; `checkout` (unrelated) stays rank 3. Both
  required IDs retained.
- **`test_mutation_observation_is_not_invented_coverage`**: a mutation observation for
  `checkout` against the changed target records `metadata.killed: false` (the mutant
  survived). `checkout` stays rank 3 (never rank 1), and the survival produces one
  explicit `coverage_gaps` entry naming `checkout` and the word "mutation" in its reason.
- **`test_duplicate_check_identity_deduplicated_without_dropping_required_ids`**:
  `checkout-a`/`checkout-b` share identical `argv`/`cwd`/`environment`; the plan merges
  them into one `checks` entry with `ids: [checkout-a, checkout-b]`, while
  `required_ids == [checkout-a, checkout-b]` keeps both original IDs.
- **`test_memory_tool_plan_checks_operation_returns_ranked_plan`**: exercises the
  `MemoryTool` wiring end to end (`operation="plan_checks"`) with the same
  regression-fixture shape as the first test; the tool's `raw.data` envelope carries the
  same `checks`/`required_ids` shape verified directly against `plan_checks()`.
