# MC13 — Execute public benchmarks and real agent episodes

Runs the MC02 (`recall_page`/`expand_artifact`), MC06 (`record_attempt`/`recall_repair_episodes`),
MC08 (recipes), MC09 (`plan_checks`), MC10 (`compare_last_success`) and MC11 (handoff)
infrastructure through real `MemoryTool` operations -- new `scripts/benchmarks/memory_datasets.py`
dataset adapters, and new episode machinery appended to `scripts/benchmarks/memory.py` -- rather than
duplicating any of that logic. All of it is invoked through the single public
`rush.tools.memory.MemoryTool.run()` surface MC14 already wired for CLI/MCP parity.

## Dataset adapters (`scripts/benchmarks/memory_datasets.py`)

`load_dataset_section(name)` loads one manifest-bound section (`longmemeval`,
`memory_agent_bench`, `swe_bench_verified`) from `tests/fixtures/benchmarks/memory_datasets.json`
and verifies the section's declared `sha256` against the actual records payload
(`json.dumps(records, sort_keys=True, separators=(",", ":"))`, SHA-256 hex) before returning
anything -- a missing `url`/`revision`/`sha256`/`license_or_terms`/`split` field or a hash mismatch
raises `FixtureError` from the pure `_validate_section()` helper, exercised directly by
`test_dataset_revision_and_hash_required` against tampered in-memory copies of the real section (no
divergence between the validator tests exercise and the one production loading uses).

`strip_longmemeval_gold(record)` splits a LongMemEval-shaped record into `(sanitized, gold)`:
`answer`, `answer_session_ids` and every per-turn `has_answer` move into `gold`; dates and session
identifiers (legitimate question context) stay in `sanitized`. `to_longmemeval_prediction()` and
`to_swe_prediction()` emit the exact native `{question_id, hypothesis}` / `{instance_id,
model_patch, model_name_or_path}` schemas each benchmark's own official evaluator expects.
`transform_memory_agent_bench()` and `transform_longmemeval_v2()` are the MemoryAgentBench and
LongMemEval-V2 compatibility adapters (V2 reuses the same gold-stripping contract plus its own
`gold_trajectory`/`expected_next_action` removal).

`run_longmemeval_case()` ingests one sanitized record's haystack turns into a **fresh temp-directory
store per call** (the same isolation pattern the pre-existing `run_memory_probe()` already used) --
so "reset the namespace between independent cases" is a structural property, not a manually-cleared
flag. A `timeout_seconds` or `max_total_tokens` overrun during ingestion still returns a
`DatasetCaseResult` (`outcome="timeout"` / `"budget_exhausted"`, `prediction=None`) instead of
raising or being silently dropped; `aggregate_dataset_results()` counts every outcome in `total`.

## Real agent episodes (`scripts/benchmarks/memory.py`)

`run_memory_episode()` is the generic episode loop: `decide_fn` receives an `EpisodeObservation`
(the task text plus the tuple of this episode's own prior real `MemoryTool.run()` results -- never a
gold answer, expected next action or graded patch) and returns an `EpisodeAction` (an operation +
kwargs, or the `"submit"` sentinel). Every non-`"submit"` action is genuinely executed against
`root`'s live `MemoryTool`; the exact, unmodified return value becomes that step's `EpisodeEvent.raw`
and its real serialized-JSON token cost (via `tiktoken.get_encoding("cl100k_base")`) is added to
`total_tokens`, uncapped per-operation -- an expansion, a recall page and a handoff receive all count
identically. Scoring (`_score_episode`) reads only real observed evidence: a `verify_attempt` event's
actual `outcome`, or a `receive` event's actual verified `ack` (never the agent's own claimed
`final` value) -- `test_handoff_score_requires_receiver_readback` asserts a false "handoff complete"
claim with no ack still scores `FAIL`.

Five named episodes (`EPISODE_BUILDERS`), each a real, distinct MC0x route:

| Episode | Real route | Notes |
|---|---|---|
| `upload-repair` | MC05/MC06 `verify_attempt` | Reuses MC05's own git+sandbox fixture shape (`tests/test_memory_verify_attempt.py`'s `_init_upload_repo`): a real git repo, a partial patch that a real sandboxed check command rejects (`outcome="failed"`), then a full patch chosen from that *observed* failure (never a gold patch) that passes (`outcome="completed"`). |
| `guest-handoff` | MC02 + MC11 handoff/receive/ack | write → handoff prepare → receive (no ack) → expand the delivered version → receive again with an `ack` whose `digest` is the receiver's own computed `sha256` of the decoded `content_base64` bytes (never a value the agent invents) -- the exact receiver-read-back-before-ack contract MC11 requires. |
| `csv-adaptation` | MC08 recipes | Records a CSV-export recipe against a real on-disk helper, then an out-of-band edit to that same file (an environment fact, not a gold hint, mirroring the plan's own "changed API rejects recipe" scenario) makes a second real `resolve` call report `usable=False` via the recipe's own real source-hash comparison. |
| `payload-check-order` | MC09 `plan_checks` | A fresh namespace has no recorded coverage evidence yet, so this exercises the honest default-order/rank-3 path -- a real result, not a fabricated ranking. |
| `diagnosis-handoff` | MC10 `last_success_diagnose` + MC11 handoff | No recorded success pointer yet, so a real `cause_state="candidate"` default, then the same real handoff/receive/expand/ack cycle as `guest-handoff`. |

`MemoryTool.run()` wraps `write`/`verify_attempt` results flatly under `raw["raw"]`, but wraps
`handoff`/`receive`/`expand`/`recipe`/`plan_checks`/`last_success_diagnose` under an additional
`raw["raw"]["data"]` envelope (confirmed by direct inspection, not assumed) -- `memory.py`'s `_data()`
helper unwraps the latter consistently across every episode builder.

## CLI wiring (`scripts/benchmarks/run.py`, `scripts/benchmarks/reporting.py`)

`build_parser()` gained `--suite {scenario,memory}`, `--variant {none,current,raw,budgeted,linked,
full,hybrid}`, `--dataset-manifest PATH`, `--seeds "11,23,47"` and `--max-total-tokens N`, additive to
the existing scenario-dispatch flags (`test_parser_options` still passes unchanged). `--suite memory`
routes to `run_memory_suite()` instead of scenario dispatch.

`run_memory_suite()`: loads the `longmemeval` dataset section (bundled fixture, or `--dataset-
manifest`'s external JSON via the same `_validate_section()` path), runs every record once per
`--seeds` value through `_variant_hypothesis()` under the requested `--variant` (kept for the
seed-noise measurement below), then runs all five named episodes once each in independent temp
directories, and writes one combined JSON report via the new `reporting.write_memory_suite_report()`
(atomic temp-file + `os.replace`, same pattern as `write_result`). `_variant_hypothesis()` maps each
named variant to a real `MemoryTool` call: `none` never calls the tool at all; `raw` concatenates the
full unbounded haystack text; `budgeted`/`current`/`full` vary only `max_tokens` on a real bounded
`recall`; `hybrid` sets `retrieval="hybrid"` and reports whatever `MemoryTool` actually returns (a
real, honest `E_EMBEDDING_UNAVAILABLE`→lexical fallback per MC12 when no embedding engine is
configured -- never a fabricated hybrid result); `linked` follows a real `recall` result into a real
`related` call. `reporting.paired_bootstrap_ci()` is a seeded (`random.Random(seed)`), pure-stdlib
paired bootstrap returning `(0.0, 0.0)` (never a fabricated interval) for empty input.

### MC13.4 fix: the report's CI was a noise check, not a cross-variant comparison

The first MC13.4 implementation's `paired_bootstrap_ci_vs_first_seed` field fed `paired_bootstrap_ci`
per-*seed* differences of a single **already-selected** `--variant`'s aggregate `scored` count against
itself at `seeds[0]` (`float(agg["scored"]) - float(aggregate_by_seed[seeds[0]]["scored"])`) --
because nothing in `_variant_hypothesis()`/`run_longmemeval_case()` depends on `seed` at all (no
randomness anywhere in the deterministic decision path), every seed produced the identical aggregate,
so this diff list was always `[0.0, 0.0, ...]` and the CI was trivially `(0.0, 0.0)` by construction,
regardless of dataset size or which variant was requested. No code anywhere actually ran more than one
retrieval variant per invocation and diffed their scores -- the field's name claimed a cross-variant
comparison the code never performed.

The fix adds `_run_variant_cases()` and `_case_completion_score()` to `run.py`. `run_memory_suite()`
now runs **every** dataset case through **all seven** named variants (`none`, `current`, `raw`,
`budgeted`, `linked`, `full`, `hybrid`) at the same fixed `--max-total-tokens` budget, in the same
run, producing one real `DatasetCaseResult` per case per variant. `_case_completion_score()` turns
each result into `1.0` (outcome `"scored"`) or `0.0` (`"timeout"`/`"budget_exhausted"`) -- the same
`outcome` field `aggregate_dataset_results()` already counted; no gold-answer correctness evaluator
exists in this benchmark, so this completion signal is the real metric available, never an invented
per-case correctness score. For each variant, real per-case differences against the `"none"` baseline
(`variant_score[i] - none_score[i]` for each case `i`, index-aligned because every variant iterates
the identical `records` list in the identical order) feed `paired_bootstrap_ci()` -- a genuine
cross-variant comparison over real per-case data, never seed noise within one variant.

The report's `paired_bootstrap_ci_vs_first_seed` field is renamed to
`paired_bootstrap_ci_seed_noise_within_variant` (same computation as before, honestly labeled as what
it actually measures -- seed-to-seed stability of the single requested `--variant`, not a
cross-variant signal) and a new `cross_variant_comparison` field is added:
`{baseline_variant: "none", case_ids: [...], per_variant: {variant: {case_scores, diff_vs_baseline,
paired_bootstrap_ci: {low, high}} for each of the 7 variants}}`.

**Honest limitation, not fabricated variance:** the bundled fixture has only 2 LongMemEval sample
cases, and at the default `--max-total-tokens 16000` every one of the 7 variants completes both cases
(`case_scores` all `1.0`) -- so every `diff_vs_baseline` is `[0.0, 0.0]` and every variant's CI is the
real, honestly computed `(0.0, 0.0)`, not a synthetic or degenerate-by-construction value like the old
field. `run_memory_suite()` now names this explicitly as a blocker whenever `len(records) < 5`: "a
sample this small cannot produce a non-degenerate bootstrap CI ... until an external
`--dataset-manifest` with more cases is supplied." A larger or harder external dataset (more cases,
tighter budgets that make variants diverge on which cases finish) is required to see a non-degenerate
interval; the bundled fixture was never expanded to manufacture one.

## Fixture (`tests/fixtures/benchmarks/memory_datasets.json`)

Three manifest-bound sections, each with a real `sha256` computed over its own `records` list:
`longmemeval` (2 synthetic LongMemEval-shaped records with `answer`/`answer_session_ids`/nested
`has_answer`), `memory_agent_bench` (2 synthetic incremental/conflict-resolution records) and
`swe_bench_verified` (1 synthetic instance-shaped record). All content is synthetic and
locally authored -- no real upstream dataset bytes are vendored into the repo, consistent with "dataset
caches stay outside Git" (plan §"Experimental protocol").

## Named blockers (Tier C, admitted evaluation -- per plan's own execution-tier split)

1. **No external dataset download.** Only the bundled synthetic sample fixture (2-2-1 records) was
   used; the full official LongMemEval cleaned-S (500 questions), MemoryAgentBench and SWE-bench
   Verified releases were never downloaded (no network/download grant is authorized by this task).
   `--dataset-manifest` is wired to accept a real external manifest+records file the moment one is
   provided.
2. **No live agent/model decision-making.** Every dataset case's "hypothesis" and every named
   episode's tool-call sequence in this run came from a deterministic (`_variant_hypothesis()`) or
   scripted (`EPISODE_BUILDERS`) decision function, never a live LLM choosing its own next action.
   No provider API key or `--allow-live-route` grant is available in this environment (same
   category of blocker MC12 named for its own missing embedding engine, and explicitly named MC13
   as that blocker's owner). All of the *mechanical* substrate a live agent would drive -- dataset
   gold-stripping, namespace isolation, real sandboxed patch verification, real handoff/receive/ack,
   real recipe/plan_checks/last_success_diagnose calls, real token accounting -- ran for real and is
   covered by the test evidence above; only the reasoning step that would choose those actions from
   an LLM is blocked.
3. **Official SWE-bench harness not run.** `to_swe_prediction()` produces the correct native
   `predictions.jsonl` schema, but `python -m swebench.harness.run_evaluation` itself was not
   invoked (no provisioned container/execution environment for that separately pinned harness, per
   plan's own "not a Rush installation command" note).
4. **Cross-variant bootstrap CI is degenerate on the bundled fixture.** The real MC13.4 fix runs all
   7 named variants over the same cases and diffs real per-case completion scores, but the bundled
   fixture's 2 LongMemEval cases both complete under every variant at the default token budget, so
   every variant's real `paired_bootstrap_ci` is `(0.0, 0.0)` -- an honest measurement of an
   insufficiently sized/varied sample, not a code defect and not fabricated variance. A larger or
   harder external `--dataset-manifest` (more cases, and/or budgets tight enough that variants
   actually diverge on which cases finish) is required to see a non-degenerate interval.

These are environment/credential/sample-size blockers on Tier C evidence specifically, not code
defects; every Tier A (deterministic, no network) case above is real, executed, measured evidence.
