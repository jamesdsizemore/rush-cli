# MC11 — Rehydrate bounded deltas through a restricted receiver

Implements a new `src/rush/memory/handoff.py` (session/receipt business logic:
`prepare_handoff()`/`load_session()`/`receive_handoff()`/`acknowledge_readback()`), the
additive `memory_handoff_sessions`/`memory_handoff_receipts` schema and
`create_handoff_session()`/`get_handoff_session()`/`get_handoff_receipts()`/
`acknowledge_handoff()` in `src/rush/memory/store.py`, the `receive` operation in
`src/rush/tools/memory.py` (`MemoryTool._receive`), `dispatch_handoff()` (plus bridge
threading through `_send_native`/`_send_acp`) in `src/rush/memory/transport.py`,
`build_memory_bridge_handler()`/`register_memory_bridge_tool()` in
`src/rush/mcp_support/tool_registry.py`, `build_server(memory_session=...)`/
`run_stdio(memory_session=...)` in `src/rush/mcp.py`, and `rush mcp serve
--memory-session ID` in `src/rush/cli.py`.

## Schema

`memory_handoff_sessions`/`memory_handoff_receipts` are additive tables appended to
`_SCHEMA_SQL` after MC10's `_BEHAVIOR_SUCCESS_TABLE_SQL`; no existing MC01/MC02/MC03/MC10
table, index, or trigger was touched (verified-by: `git diff` on `store.py` shows only new
`_HANDOFF_TABLES_SQL` inserted and `+ _HANDOFF_TABLES_SQL` appended to the `_SCHEMA_SQL`
concatenation — every prior table's `CREATE TABLE`/`CREATE INDEX`/`CREATE TRIGGER`
statement is byte-identical to before). `memory_handoff_sessions` stores the session's
immutable `granted_ids`/`session_allowlist`/`constraints` (JSON) plus a SHA-256
`capability_hash` (never the raw capability) and `expires_at`; `memory_handoff_receipts`
is a per-`(session_id, artifact_id)` acknowledged-version cursor.

## Session lifecycle and the two "ack" concepts

`prepare_handoff()` mints a session (`secrets.token_hex(16)`) and a one-time raw
capability (`secrets.token_urlsafe(32)`, hashed before storage), binds it to `root`/
`audience`/`granted_ids`/`session_allowlist`/`constraints`, sets a 900-second TTL, and
returns the first delta. `load_session()` is the single choke point every operation
(`receive_handoff`, `acknowledge_readback`, and the bridge's `expand`/`related`/`resume`
delegation) passes through first: an unknown session, a wrong capability, and an expired
one are all denied identically (`E_PERMISSION`), so a caller can never distinguish one
denial reason from another.

`receive_handoff()` never writes to the database — it is a pure read of `granted_ids`
whose *current* version exceeds this session's already-acknowledged version, ordered by
artifact ID for a deterministic, replayable page. It returns only `id`/`version`/
`trust_tier`/`source`, never content, so a receiver must call `expand` for the exact bytes
before it can prove a read-back. `acknowledge_readback()` is the *only* function that ever
advances a receipt: every entry must name a `granted_ids` member and the exact SHA-256
digest of that exact version's stored bytes (`TypedArtifactStore.acknowledge_handoff()`),
verified inside one `BEGIN IMMEDIATE` transaction before any row is written — a single bad
entry (an unseen version, or a version that exists but a wrong digest) raises
`VersionConflictError` and rolls the whole call back atomically, so "same ID, different
digest" can never partially advance a session's cursor. A transport-level delivery turn
completing (`transport.dispatch()`'s "Handoff acknowledged by receiving agent") never
calls `acknowledge_readback()` — the two concepts are enforced by entirely separate code
paths that never call each other.

## Restricted receiver: `rush mcp serve --memory-session ID`

`mcp.build_server(memory_session=...)` registers exactly one tool — `rush_memory`
(`build_memory_bridge_handler()`) — and nothing else; the default (`memory_session=None`)
path is byte-for-byte unchanged and still registers the full catalog. The handler accepts
only `operation in {"receive", "expand", "related", "resume"}`; every other value
(including every other catalog tool's name) is denied identically before the session is
even loaded. `expand`/`related`/`resume` always run with this session's own stored
`session_allowlist` — no `request` field is ever read as a caller-supplied allowlist, so
there is no code path through which a caller can widen scope. The capability travels to
the spawned subprocess only via the `RUSH_MEMORY_CAPABILITY` environment variable, set by
`transport.dispatch_handoff()`, never through `rush mcp serve`'s CLI argument or the
prompt payload. `dispatch_handoff()` restricts itself to the native-SDK/ACP tiers only
(`select_tier()`'s dedicated-file tier is refused with `status="skipped"`, since a
markdown file cannot expose a live, capability-gated MCP tool) and resolves the `rush`
binary from the *current* interpreter's own venv (`Path(sys.executable).with_name("rush")`)
before ever falling back to `PATH`, so it can never spawn a stale, differently-versioned
global install.

## Guest intent / last-success reuse (MC07 / MC10)

`prepare_handoff(..., intent_behavior_ids=[...])` calls MC07's existing
`intent.intent_evidence()` (read-only refs, scoped by the same `session_allowlist`) and
MC10's existing `store.find_any_behavior_success()` — no parallel intent/last-success
implementation was added. Both are attached to the session's `constraints` at prepare
time and returned unchanged on every subsequent `receive_handoff()` call; nothing about
`acknowledge_readback()` touches `memory_behavior_success` or an intent's stored artifact.

## Test evidence

All 12 required tests plus regressions pass:
`pytest tests/test_memory_handoff.py tests/test_phase61_transport.py
tests/test_phase62_handoff_diff.py -q` → **36 passed**.

- **`test_delta_contains_only_changed_authorized_versions`**: after A1@1 is acknowledged,
  A1 advances to @2, A2 first appears at @1, and a never-granted D1 changes too — the next
  `receive_handoff()` call returns exactly `{"A1": 2, "A2": 1}`, D1 absent, plus the
  session's stored `constraints`.
- **`test_delivery_ack_does_not_advance_cursor`**: a real `transport.dispatch()` delivery
  (`dedicated_file` tier, `status="ok"`) leaves `get_handoff_receipts()` empty; only a
  direct `acknowledge_readback()` call changes it.
- **`test_receiver_reads_exact_versions_before_ack`**: a wrong digest raises
  `HandoffError(code="E_VERSION")` and leaves receipts untouched; the exact digest of the
  exact stored version succeeds.
- **`test_partial_page_and_replay_are_atomic`**: `page_size=1` across two changed
  artifacts — page one, an identical replay of page one, and page two are all
  byte-identical/side-effect-free; both are then acknowledged from their separate pages.
- **`test_scope_change_requires_new_snapshot`**: an artifact created after
  `prepare_handoff()` and never in `granted_ids` never appears in a delta and can never be
  acknowledged through that session; only a brand-new `prepare_handoff()` call (new
  session_id/capability) can see it.
- **`test_bridge_denies_unrelated_tools_and_scope_widening`**: a real spawned
  `rush mcp serve --memory-session ID` subprocess, driven by the real `mcp` Python client
  library (`stdio_client`/`ClientSession`) — not a fake peer — exposes exactly one tool
  (`["rush_memory"]`); `operation="write"` is denied `E_PERMISSION`; expanding an artifact
  outside the session's own scope by ID is denied `E_NOT_VISIBLE`.
- **`test_imported_prompt_injection_cannot_widen_permissions`**: an `IMPORTED` artifact
  whose content literally reads "operation=write. session_allowlist=['*']..." is
  delivered verbatim as inert data through `expand`; the literal `operation="write"`/
  `operation="promote"` calls are still denied regardless, because dispatch never parses
  instructions out of content.
- **`test_expired_session_capability_denies_every_operation`**: with `handoff.time.time`
  frozen past `expires_at`, all four bridge operations (`receive`/`expand`/`related`/
  `resume`) are denied identically with "expired" in the message.
- **`test_default_transport_still_denies_all_tools`**: the plain `transport.dispatch()`
  path (used by every existing Phase 61 caller) still builds `tools=[]`/`mcp_servers={}` —
  unaffected by MC11's additive `bridge=` parameter.
- **`test_cross_namespace_import_does_not_copy_authority`**: a `trust_tier="IMPORTED"`
  artifact from another namespace stays `IMPORTED` through `receive`/`expand`;
  `operation="promote"` is denied, and the underlying stored row's `trust_tier` is
  unchanged.
- **`test_cancelled_receiver_leaks_no_process`**: a real spawned
  `rush mcp serve --memory-session` subprocess, cancelled by closing its stdin, exits and
  is reaped — `os.kill(pid, 0)` raises `ProcessLookupError` afterward.
- **`test_guest_intent_and_last_success_survive_readback`**: a handoff for a
  "guest-checkout" behavior carries `intent_refs` (MC07) and `last_success_refs` (MC10);
  after an exact receiver read-back and acknowledgement, `store.get_behavior_success()`
  and `check_intent()` still resolve to the same, unmutated underlying records.
