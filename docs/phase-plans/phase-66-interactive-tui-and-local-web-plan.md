# Phase 66: Interactive TUI and per-project local web application

**Work queue: §4, P66-01.1 through P66-07.4.** Status: planned development, not implemented. Build both interfaces against the product behavior in §3: neon blue/pink/purple, integrated motion and an interactive project map as the browser opening view. A single printed Rich layout, a static report page, API-only backend or a UI that merely tells users to run terminal commands does not satisfy this phase.

## 1. Goal, prerequisites and boundaries

Make Rush usable through an organized, colorful, animated TUI and a local web application. Both use Phase 65's complete install/connect/provision/scan/handoff/rescan workflow and Phase 63's memory services. The browser has persistent project/repository selection and displays **overview, scan results, memory administration, token use, Git history and every Rush-generated output**. Baseline audit: [F36–F41](../reports/phase-64-66-application-review.md). Required execution order remains 64 → 63 → 65 → 66.

Binding: root `AGENTS.md` including corrected product-interface scope, `docs/templates/task-block-template.md`, accepted ADR-0016/0045, Phase 65 contracts. Stay off `main`; no production release, hooks, paid provider invocation or destructive user-data action is authorized by planning. UI design and implementation are in scope. No Figma/editor-style design tooling is needed to fulfill the requested application interfaces.

## 2. Implementation boundaries

CLI entry points remain in `src/rush/cli.py`; terminal application code is owned by `src/rush/tui.py` and the named terminal modules. Local HTTP/auth/state code is owned by `src/rush/dashboard/`. P66-02 adds the real project-map data projection and browser renderer; P66-03 adds persistent terminal interaction. Each action calls Phase 65's shared project/run/memory implementation, with identical permissions and evidence across interfaces. No UI handler invokes arbitrary shell strings or writes memory tables directly.

Start interfaces before long work. Bind ordered progress, cancellation, selected project and detail requests to explicit project/run IDs. Retain immutable historical run identities, sanitize all displayed source/output, and reject stale cross-project responses. Browser and terminal rendering must satisfy the required interactions and animation; printed layouts and static cards are not completed implementations.

## 3. Shared product and API contracts

### 3.1 Information architecture

Both surfaces must expose persistent project identity and Overview, Scans, Memory, Tokens, Git, Artifacts and Setup/Agents capabilities. **Browser opening view: the interactive project map**, connecting files, findings, memories and agents. Summary remains accessible; it does not replace the map as the project's default entry. Selecting a node focuses its connected neighborhood and opens contextual details while preserving the node's identity and a route back to the whole project. Terminal navigation exposes the same project relationships through expandable, keyboard-selectable groups. The project selector is always reachable and switching projects changes every section, pending request and action context. Selecting a run preserves its own historical project/source identity. With no project selected, offer select registered project, add existing folder, create new project folder and choose later; configuration follows the explicit project choice. These call Phase 65 shared operations. Disconnected agents, missing engines and failed jobs remain visible, never replaced with example data.

Overview shows root, worktree/branch, languages/frameworks, readiness, latest coverage, unresolved findings, active jobs, agent/memory connection state and last update. Scans show complete per-tool statuses, engine versions, skipped/blocked reasons, grouped findings with original provenance, filters, path/line navigation, raw redacted reports and handoff/rescan controls. Long reports are paginated/expanded by identity, not dumped into every refresh.

Memory provides scope/type/trust/source/freshness filters, search, exact expansion, relationship navigation, edit/propose/promote, archive/delete and maintenance controls through Phase 63. User/project/session/agent scope is explicit on every write. Deletion and promotion show the selected records and consequences before applying; no silent cross-project mass action. Tokens show actual usage separately from estimates/avoided payload, per project/run/agent/session, with source and encoding provenance. No fabricated savings percentage.

Git shows branch/dirty state, commits, authors/timestamps, changed files and bounded diff expansion, with scan/repair links where evidence exists. All Git reads use repository-scoped argv, never shell text or unbounded log. No commit/reset/push UI is required by this phase. Artifacts indexes all shared project evidence types, including unfamiliar types with a safe metadata/detail view; an output need not wait for a custom chart to become accessible.

### 3.2 HTTP and action boundary

Canonical endpoints: `GET /api/projects`; authenticated `POST /api/projects` dispatching Phase 65 `rush_project` add/create with §3.6 fields, physical root validation and explicit artifact-write grant; `GET /api/projects/{project_id}/snapshot`; `GET /api/projects/{project_id}/events?after=<sequence>`; `GET /api/projects/{project_id}/artifacts/{artifact_id}`; `POST /api/projects/{project_id}/actions`. The global add/create endpoint works with an empty registry and returns the new/existing project ID; it never requires a preexisting selected project. Snapshot includes schema version, project ID, revision/sequence and paginated section data from Phase 65. Actions are allowlisted operation names with typed arguments, expected source/plan identity and explicit grants; the same shared invocation path enforces them. Start returns 202 plus run ID; progress is queried separately. Stale project/source identity returns 409 with recovery instructions, missing resource 404, permission denial 403, malformed input 400.

Use existing SessionAuthManager for per-server token generation/verification. Browser first-load token is transferred through URL fragment, exchanged using Bearer-authenticated `POST /api/session`, then removed with `history.replaceState` and discarded. Exchange sets a random per-server, host-only, HttpOnly, SameSite=Strict session cookie without Domain; server-side session is scoped to that server and expires on shutdown or eight hours. Browser requests use this cookie plus a per-session CSRF header on mutations. `GET /api/session` restores session/CSRF state on page reload under §3.7 exact Host/Origin/Fetch-Site rules, so reload retains active run/selection without persisting Bearer in localStorage or URLs. Programmatic HTTP clients may continue Bearer authentication through the same verifier. On server restart/expiration show reauthorization and accept a freshly generated launch token through §3.7 private reconnect control without losing persisted run history; never silently bypass auth. Bind only loopback; exact host/port and Origin checks precede action dispatch. Non-browser stdio MCP remains unchanged. Every response is sanitized/serialized before response headers; exceptions return a structured error and request ID without secret stack traces.

A server's auth/state cannot affect another server. One shared server can serve multiple projects, with per-browser selected project; project IDs and physical roots are validated on every request. Responses carry project ID/sequence so stale responses after a project switch are discarded. No website can trigger installation, memory modification or code writes merely by reaching loopback. Content Security Policy, safe text rendering, exact-origin actions and validated artifact MIME/downloads defend findings/source text as untrusted data.

### 3.5 Project map schema, layout and large-repository behavior

`build_project_map(snapshot, *, run_id=None, node_types=(), severity=(), status=(), query='', center_id=None, cursor=None, limit=200)` returns `{schema_version:1, project_id, run_id, source_identity, sequence, nodes, edges, total_nodes, total_edges, next_cursor, groups}`. All IDs are opaque existing evidence IDs prefixed by kind; file ID is `file:` plus SHA256 of normalized project-relative POSIX path. Node is `{id, kind, label, artifact_id, path, status, scope, source_identity, count, expandable}`; kind is `project|directory|file|finding|memory|agent|group`. Unavailable optional values are null, not invented strings. Edge is `{id, source, target, relation, evidence_ids, source_identity}`; relation is `contains|reports|cites|produced_by|assigned_to`. Contains derives only from recorded file path/registry hierarchy, reports from canonical finding.path, cites from explicit memory/source citations, produced_by from producer provenance, assigned_to only from actual handoff assignment. Never infer memory relevance or agent authorship from matching labels. Agent nodes with no recorded relationship remain in Unlinked group; selecting them shows that fact.

`groups` entries are `{id, kind, label, member_count, cursor}` and are explicit aggregation UI, never simulated file/evidence records. Group count equals full filtered membership, not rendered children. Filtering accepts kind multiselect, severity/status multiselect and case-insensitive literal ID/label/path query (maximum 256 code points); it never silently filters by installed engine. Filtered-out endpoints do not generate dangling edges. Inspector can expand a cited artifact without making it part of the filtered map. Every returned edge's endpoints exist in the returned node set, or an explicit group endpoint represents the offscreen collection.

Deterministic polar layout uses project at (0,0), kind sectors clockwise: files/directories −150°..−30°, findings −30°..60°, memory 60°..150°, agents 150°..210°. Sort each sector by normalized path then stable ID. Overview ring radii are 180px for directory/kind groups and 340px for visible members; child rings add 140px. Within each ring, angle is sector start plus `(index+.5)*sector_width/member_count`. Node radii: project 28px, groups 20px, file 10px, finding 9px, memory/agent 12px. Edges use cubic Bézier with control points at .45 and .55 of radial displacement. No random positions, iterative physics or layout changes from request ordering. Focus neighborhood uses selected node at local origin and one-hop relations on 220px ring; second-hop records appear only on explicit Expand and use 360px ring. Back restores previous camera/filter/selection history, not a new random overview.

Map viewport supports wheel zoom .35×–2.5× around pointer, drag background pan, `+`/`-` zoom 20%, `0` Fit, arrows move keyboard selection in stable clockwise order, Enter selects, Escape returns one neighborhood, `/` focuses search. SVG node has accessible button name and roving tabindex; adjacent semantic relationship list exposes identical records and actions to assistive technology. No action requires dragging. Tooltip appears after 300ms hover/focus and closes on movement/Escape.

Hard rendering bound: 200 nodes and 400 edges at once; never cut the underlying evidence inventory. Repositories above bound open grouped overview with exact counts and server-paginated members (100 per page). Directory grouping starts with first path component, splitting only selected branch. Dense relation sets show counted group edges, expandable through the same cursor contract. Selected node and its inspector remain visible even if pagination changes. Server projection reads manifest indexes, not whole raw artifacts; large input enumeration occurs once per immutable snapshot and is cached by project/source/filter identity. Cache invalidates on sequence/source identity change. Fixture with 10,000 files and 30,000 findings must retain totals 40,001 including root, expose every ID across pagination, never exceed visible bounds and keep action response ≤250ms after indexed snapshot exists; measure on recorded test hardware, required failure cannot be waived by dropping evidence. Initial shell is interactive before map request finishes.

### 3.7 Exact local-server security and recovery

Bind numeric `127.0.0.1` only; configured port 0 selects free port, explicit port range 1024–65535. Compare parsed Host authority to `127.0.0.1:<bound-port>` or `localhost:<bound-port>` exactly, rejecting userinfo, suffixes, duplicate Host, whitespace and invalid ports. Browser Origin must equal actual launch origin on every mutation/session exchange; GET may omit Origin only with absent/same-origin `Sec-Fetch-Site`, rejecting cross-site requests. No CORS allow headers. Bearer programmatic requests with absent Origin are accepted only with valid exact Host and token. Header/body limits: 16KiB aggregate headers, 64 fields, 256KiB JSON body, 5s socket read timeout; Content-Type must be `application/json` for JSON POST, Content-Length required, transfer encoding rejected. Eight simultaneous requests per server; excess returns 503, no unbounded thread spawning. Rate limit session bootstrap to 10 failures/minute per server; other actions 60/minute/session with 429 Retry-After:1. Expensive work is queued through existing run lifecycle, not held in HTTP worker.

Session cookie name is `rush_session_<random-server-id>` to avoid same-host cross-port collisions; value 256-bit CSPRNG, Path=/, HttpOnly, SameSite=Strict, Max-Age=28800, no Domain. It is HTTP loopback and therefore does not claim TLS/Secure transport. Server stores token digests and session records per instance; compare secrets with `hmac.compare_digest`. CSRF token is independent 256-bit random, delivered by session endpoint, required as `X-Rush-CSRF` on cookie-authenticated mutation, compared constant-time after Origin check. Cookie from another port/server is never looked up by this server's name. Bearer bootstrap expires after first exchange or 5min; CLI `rush dashboard --reconnect` issues a new one-use launch URL for existing server through user-owned control state, never prints cookie/CSRF or resets scans. Reconnect UI accepts the fresh fragment token; Ctrl+R restores valid cookie session and selected project/run. Shutdown invalidates sessions while durable run history remains. Expired session cannot cancel or restart a job until authenticated again.

Reconnect control is implemented in `src/rush/dashboard/auth.py::issue_bootstrap` and `src/rush/dashboard/server.py::reconnect_dashboard`, not another service. Active server writes one private descriptor `<user-rush-data>/dashboard/<server-id>.json` containing schema_version, PID, start nonce, bound port and independent 256-bit control capability using existing atomic/private-file helpers. POSIX directory/file modes 0700/0600; Windows user-only data-directory ACL must be verified before persisting capability, otherwise launch fails with explicit privacy error. Descriptor is never a project artifact or browser response. `--reconnect` selects the newest live descriptor unless `--server-id` specified, verifies server ID/PID/start nonce through private `GET /api/control/health`, then calls `POST /api/session/bootstrap` with `X-Rush-Control`; this endpoint accepts no cookie or ordinary Bearer and returns new one-use bootstrap to CLI only. Private `GET /api/control/health` requires `X-Rush-Control` and returns `{schema_version:1,server_id,pid,start_nonce}` only after exact bound Host, absent Origin and constant-time capability check. Public `/api/health` remains readiness-only. These same control checks are mandatory for bootstrap issuance; cookie/Bearer credentials alone receive 401 on either private endpoint. Server removes descriptor on normal shutdown; stale descriptor is reported and removed only after PID/start-nonce mismatch proves ownership stale. Multiple servers never share control capabilities. This control route rotates only bootstrap, not active sessions/runs.

Serve script as `/assets/project_map.js` and create `/assets/application.js` from owned `src/rush/dashboard/application.js`; styles as `/assets/dashboard.css` serialized by `static_assets.py`. No inline event handlers, `eval`, unsafe HTML insertion or remote assets. CSP exactly `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; font-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'self'`. Add `X-Content-Type-Options:nosniff`, `Referrer-Policy:no-referrer`, `Cache-Control:no-store` to API/HTML and private session responses.
