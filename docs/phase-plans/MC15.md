   timeout-only patch: `PatchSandboxManager` creates a real git worktree, `PatchApplier`
   applies the patch, `PatchVerifier` runs the real `check_upload.py` subprocess; asserted
   outcome `"failed"`, real nonzero exit code, `ToolResult.status == "fail"`.

   `"completed"`, real exit `0`, real `"OK"` stdout, `ToolResult.status == "ok"`; source
   checkout byte-identical before/after both attempts, no leaked sandbox worktrees.

   `resolve_recipe` resolve `upload.py`'s current on-disk source (asserted `"def upload"` in
   the resolved excerpt); `record_recipe_outcome` links the recipe to the exact
   `sandbox_verification` receipt from step 3 (`evidence_kind == "sandbox_verification"`,
   `outcome == "completed"`) — a bare `passed=True` claim is structurally impossible (no
   such parameter exists), so this proves the recipe's one passing outcome traces to a real
   executed check, not an assertion.
5. **Ranked check evidence** (MC09) — a seeded `tests_contracts` regression finding for
   `upload.upload` makes `plan_checks` (both through `MemoryTool.run(operation="plan_checks")`
   and the bare `rush.memory.verification.plan_checks` function) rank `check-upload` first
   without dropping the unrelated required `check-unrelated`; the ranked check's own `argv`
   is asserted equal to the exact command step 3's real sandbox execution ran.
6. **Confirmed intent bound to real evidence** (MC07) — `check_intent(..., current_revision=
   base_commit)` reads the step-1 intent's `check_refs=[receipt from step 3]` and returns
   `passed=True`, bound to the exact real commit the sandbox ran against.
7. **Real local receiver** (MC11) — `prepare_handoff` grants the intent, the verified
   receipt and the recipe (three distinct real `source` values, so genuine multi-source
   grant), then a real, spawned `rush mcp serve --memory-session <id>` subprocess — driven
   by the real `mcp` client library, not a stub — lists exactly one tool (`rush_memory`),
   calls `receive` (bounded delta, exact granted ids/versions), calls `expand` for each
   granted artifact and asserts the base64-decoded bytes are byte-identical to the sender's
   own `TypedArtifactStore.get_version_content`, acknowledges an exact SHA-256 read-back
   digest per artifact, and replays the identical `ack` a second time.
