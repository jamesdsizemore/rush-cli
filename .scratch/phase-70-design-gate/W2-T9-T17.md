## T16: Preserve scope, per-engine outcomes, and recoverable output

### 1. Required behavior
- **S16.1 Scope on every catalog result.**
  - Every catalog ToolResult carries `metadata.scope` in legacy form or `extensions.metadata.scope` in strict V1 (via `adapt_legacy_tool_result`, `contracts/results.py:641-645`). No new top-level key.
  - Admin and service frames are unchanged (`tests/test_phase54_operation_adapters.py`).
- **S16.2 Engine entries.** Every engine-backed child records a per-engine entry in `metadata.engines`. Missing engines get `version:null` plus `version_unavailable_reason`. Multi-engine results, lint, suites and scans retain every child.
- **S16.3 Precedence.** Status precedence is error>fail>warn>skipped>ok, and mixed ok+skipped becomes warn. Exact exits: ok/skipped=0, warn/fail=1, error=2.
- **S16.4 Compact output.** `--result-view compact` (CLI) and `result_view="compact"` (MCP):
  - defaults to 50 findings and 32,768 bytes of the whole serialized response;
  - `limit` must be an integer 1-50 and `max_bytes` 4,096-65,536; bool is rejected;
  - it needs the cache-write grant before any engine spawn;
  - it stores the full redacted result in CCR, then returns a projection with `metadata.delivery`;

1. **Status (routing.py).**

2. **Per-engine entry (subprocesses.run_engine).**
   - A contextvar spawn recorder, set around `engine.run` and `normalize`, is read by `run_subprocess`. It records the resolved `argv[0]`, the actual cwd (`os.getcwd()` when None) and a kind (`main` or `version_probe`).

   - `sha256` comes from `binaries.compute_file_sha256`, cached by `(path, st_ino, st_size, st_mtime_ns)`.
   - `consumed_file_count` counts argv entries that are existing files (`explicit_arguments`). If any argv target is a directory, it is `null` with coverage `unavailable` and reason `engine_discovers_directory_contents`.

3. **Aggregation.**

4. **Scope default (executor).**

   - For `kind=="operation"`: `file_count:null` and `reason:"not_file_analysis"`.
   - Merge into ToolResultV1 via `extensions.metadata`.
   - On a cache hit (`executor.py:445-447`), return a copy with `metadata.execution.cache={"hit":true,"cache_key":key}` and never rewrite the original scope.
5. **Lint instrumentation (T16 owns lint).** Requested = files matched under the targets. Consumed = files passed explicitly to executed engines, as normalized physical identities `(st_dev, st_ino)`, recording aliases. Ruff also receives the root directory at `ruff.py:59-66` → `consumed_file_count:null`, coverage `unavailable`, until T13's decision.
6. **Transport parameters.**
   - CLI: `result_view_options` adds `--result-view [full|compact]`, `--limit INTEGER`, `--max-bytes INTEGER`. The factory's `--no-cache` becomes `req["cache_policy"]="bypass"` (the resolver already honors it at `resolver.py:311-314`).
   - MCP: `make_tool_wrapper` publishes `result_view: Literal["full","compact"]|None`, `limit: int|None`, `max_bytes: int|None`, `no_cache: bool=False`, and `allow_cache_write` only when the tool lacks it.
   - The wrapper consumes these and never forwards them into `req` typed args (`no_cache` becomes `cache_policy`), so `**kwargs` tools never receive them.
   - A collision with a declared tool parameter is a registration-time `SignatureAdaptationError`.
7. **Compact ordering (CLI `_run_tool` and MCP wrapper).**
   1. Validate the parameters (`RESULT_VIEW_INVALID`).
   2. Check the no-cache conflict (`RESULT_VIEW_CACHE_CONFLICT`).
   3. Require the cache-write grant (`RESULT_VIEW_REQUIRES_CACHE_WRITE`, with help naming full mode and `--allow-cache-write`).
   4. Preflight containment with `PhysicalRoot(root).open_contained(".rush/cache/ccr.db", purpose="write")` (no creation).
   5. Execute.
   6. Redact the full result with `sanitize_value`.
   7. Store `canonical_json({version:1, created_at:<UTC ISO>, full_result, finding_ids})` via `CCRStore.store_chunk`, giving `handle = sha256` (`ccr_store.py:35`).
   8. Project.
   - `canonical_json` is `json.dumps(sort_keys=True, separators=(",",":"), ensure_ascii=False, allow_nan=False).encode()`.
   - `finding_ids[i]` is the finding's `fingerprint`, or sha256 of the canonical finding.
   - A store failure (`sqlite3.Error`/`OSError`) returns an error with code `RESULT_STORE_FAILED`, `metadata.delivery={schema_version:1, complete:false, result_handle:null, analysis_status:<full>}`, exit 2.
   - SARIF and HTML exports use the full redacted result.
8. **Projection.**
   - Envelope: `{tool, engine, engine_version, status:<full>, duration_ms, summary, findings:page, raw:{content_omitted:true, reason:"compact_view", bytes, sha256}, metadata:{...original metadata..., delivery:{schema_version:1, view:"compact", result_handle, total_findings, returned_findings, complete, next_cursor, max_bytes, full_result_bytes}}}`.
   - Measure it with the real serializer. CLI: `len(json.dumps(proj, indent=2, default=str).encode())+1`. MCP: `CallToolResult(content=_convert_to_content(proj), structuredContent=<the model-dumped proj when the tool has an output schema>).model_dump_json(by_alias=True, exclude_none=True)` plus a fixed JSON-RPC reserve of 96 bytes, documented.
   - While over budget: first replace oversized variable fields with `{content_omitted:true, ...identity}`, largest first, in this order: raw, engine summaries, scope lists, memory receipts, finding values. Then drop trailing findings (binary search) and set `complete:false` and `next_cursor`.
   - If the minimum envelope (zero findings, everything referenced) still does not fit, return `RESULT_BUDGET_TOO_SMALL` with no handle.
9. **Cursor.** `base64url(canonical_json({v:1, root:sha256(str(logical_root)), handle, view, next, limit, max_bytes}))`, unsigned. Validation is field equality against the current request plus `0<=next<=total`; failure gives `RESULT_CURSOR_INVALID`. `cursor` and `offset` together give `RESULT_VIEW_INVALID`.
10. **Retrieval** (`continuity/context.retrieve_result_view(root, handle, *, view, cursor, offset, limit, max_bytes)`).
    1. Require the handle to be 64 lowercase hex characters.
    2. `PhysicalRoot(root).open_contained(".rush/cache/ccr.db", "read")`, rejecting symlinks.
    3. Missing gives `RESULT_MISSING`.
    4. Open `mode=ro` (no constructor, no touch, no telemetry).
    5. No row gives `RESULT_MISSING`.
    6. `sha256(content) != handle` gives `RESULT_CORRUPT`, as does a schema mismatch.
    7. The `result` view pages findings with the same projection. The `bytes` view slices the stored bytes at UTF-8 boundaries and returns `raw={view:"bytes", offset, length, total_bytes, sha256, content, next_offset}`, with the length chosen by binary search under the budget.
    - No view keeps the existing `retrieve_context`.
    - Plumbing goes through `SessionContinuityTool.run` and `__call__` (kwargs `view`, `cursor`, `offset`, `limit`, `max_bytes`), `mcp.rush_context_retrieve`, and CLI `context retrieve` options.
    - T23's `rush_status(operation="result", ...)` calls this same function.
