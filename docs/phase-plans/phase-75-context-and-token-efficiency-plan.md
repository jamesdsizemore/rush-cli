# Phase 75: Context and token efficiency with measured task quality

Status: implementation specification; no application implementation performed by this planning task. Baseline `ddc064117e971b48e29100004052e876e456faf2`, 2026-09-25. Phase number identifies ownership, not a requirement to finish Phases 72–74 first.

## 1. Goal, scope and binding contracts

Deliver less irrelevant context and fewer total model tokens for correctly completed work across Rush, its memory and coding agents. Connect currently dormant reduction utilities to real public paths; enforce actual budgets; support selective recovery, local queries and delta delivery; account for provider consumption and total work; improve selection from observed outcomes without sacrificing constraints or correctness.

Read `AGENTS.md`, `docs/templates/task-block-template.md`, [shared memory program contract](memory-program-contract.md), and the controlling [memory review](../reports/memory-system-implementation-review-2026-09-25.md), especially §§6.12–6.13/8/11. Preserve all assigned F20–F22, A04, E16, R07/R19, TR01–TR11, TC01–TC04/TC06–TC07/TC10–TC12, and AP08 measurement outcomes. Host discovery TC05/TR07 integrates with 73-T03; AST graph facts integrate with 74-T01; defensible memory recovery integrates with 72-T01/T02. These are task-level edges, not whole-phase gates.

Scope includes source selection, tool/result delivery, CLI/MCP/TUI/dashboard visibility, providers, memory construction/recall/expansion, subagents, retries, optional learned compression and real evaluation. Non-goals: another memory database, generic arbitrary-code execution sandbox, model-weight training, speculative savings, automatic paid calls or model downloads, loss of canonical output, unsupported host injection, and changing unrelated Git UI. Native provider caches/compaction supplement portable memory; they do not replace it.

## 3. Concrete interfaces and algorithms

### 3.1 Evidence selection and budget contract

Extend existing context-pack inputs with strict optional `task`, `encoding`, `max_bytes`, `required_artifact_ids`, and `view` (`canonical`, `compact`, `outline`) fields through shared request normalization. Preserve legacy path/symbol/budget calls. New selectors are optional additions, not silently reinterpreted old arguments.

Assemble candidates from authorized memory and source refs. Reserve envelope/error/recovery overhead; pin explicit applicable user constraints and required evidence; deduplicate only identical evidence ID/version/projection, never distinct invocations. Rank remaining candidates lexicographically by explicit selection, exact qualified target, directly implicated failure/check/dependency, task lexical relevance, then stable ID. Include complete independently meaningful evidence units while count/byte budget permits. Add source-backed graph neighbors from 74-T01 with their coverage labels; never imply absent dynamic edges prove no impact. Excluded evidence retains typed IDs/reasons and selective recovery. If pinned evidence plus minimum envelope cannot fit, return `budget_too_small` and required minimum without a malformed payload or fictional success. No million-token intermediate pack.

Adaptive ranking (75-T07) changes only nonmandatory nonmemory candidate order after an attributable outcome; Phase 74 exclusively orders memory evidence. It cannot change trust, scope, freshness, mandatory checks or user requirements. Tokenizer name/version and model basis travel with the packet; unknown host encodings stay estimated. Server-wide serializers and MCP framing add overhead outside an inner text count: measure the actual host projection in delivery receipts and clearly delimit any count the server cannot observe.

### 3.2 Typed local result query and delta protocol

Add `operation="context_query"` to `SessionContinuityTool`, surfaced by `rush context query` and the existing `rush_continuity` MCP tool. Strict request fields: `schema_version=1`, `source_kind` (`scan`, `memory`, `context`), immutable `source_id`, optional `base_source_id`, `filters={}`, `fields=[]`, optional `group_by`, `limit` 1–200 default 50, cursor, encoding/token/byte budget and optional receiver acknowledgement ID. Unknown keys, explicit null for nonnullable fields, mixed source predicates and invalid enum values fail with `E_QUERY_SCHEMA` before effects. No shell/SQL/code text, arbitrary expressions, or cross-project joins. Execute filters/group/count on complete authorized retained snapshots, not one UI page.

Exact version-1 predicate/projection schema (`max_hops` is restricted to one or two):

| Source | Allowed filters (AND between keys; membership within a list) | Allowed projected row fields | Grouping |
|---|---|---|---|
| scan | `path_prefix: str` normalized relative path at segment boundary; `severity_in: list[error,warning,info]`; `rule_id_in: list[str]`; `change_in: list[added,changed,resolved,unverified,unchanged]` only with baseline; `changed_files_only: bool=false` using captured source diff; `test_outcome_in: list[passed,failed,skipped,error]` only for retained test results; `touches_symbol: {symbol_id: str, graph_revision: str, relation: calls_or_covers, max_hops: int=1}` | `id,path,line,column,severity,rule_id,message,status,engine,engine_version,test_id,test_outcome,symbol_ids,relation_evidence,change,source_ref` | `severity,rule_id,path,test_outcome` |
| memory | `subject_in: list[str]` validated against canonical subjects; `freshness_in: list[current,stale,unknown]`; `artifact_id_in: list[str]`; `path_prefix: str` on anchored source only | `id,artifact_version,subject,summary,source,owner_scope,freshness,authority,symbol_ids,source_ref` | `subject,freshness` |
| context | `artifact_id_in: list[str]`; `path_prefix: str`; `symbol_id_in: list[str]`; `freshness_in: list[current,stale,unknown]` | `id,artifact_version,path,symbol_id,language,summary,freshness,source_ref` | `path,language,freshness` |

Empty `fields` selects the complete listed compact row for that source; explicit subsets cannot remove `id,source_ref`. Optional unavailable row fields are null; predicate comparisons against null do not match. Empty membership list matches nothing. `group_by` emits `{key: value|null,count: int}` plus total matched rows and source handles, not arbitrary aggregates. Authority/visibility filters always precede query filters and joins; a requested stale/unknown label never bypasses Phase 72 ordinary-recall rules. Lists are limited to 100 values and strings to 4096 UTF-8 bytes; unknown symbols are an explicit empty result with `symbol_not_found`, not a fabricated relation.

`touches_symbol` joins failed test rows to Phase 74 qualified symbols through captured test-source identity and current direct call edges or measured coverage edges, at most two hops. Source test results must carry exact `test_id`, outcome, path/span and immutable invocation/revision; extend the existing retained test-result adapter when these fields are absent. Match exact qualified identities, not simple-name/substring guesses. Return each relation's kind, graph revision and test/coverage receipt. Missing test identity, unavailable engine, stale graph or unsupported language returns `query_incomplete` with known rows, unresolved counts/reason and recovery; it cannot assert zero affected tests or complete absence. No read triggers indexing or engine execution. Test the public query “failed tests touching this symbol” against canonical multi-page records, duplicate names, measured coverage and static-only edges.

Return canonical status, source/revision/hash, exact matched/selected/omitted counts, required diagnostic/permission fields, result rows and bound cursor/recovery. Preserve the source's execution status separately from `query_status` (`complete`, `incomplete`, `invalid`, `denied`, `unavailable`). Delta baseline identity includes project, worktree, branch/ref, source revision, tool and engine version, configuration/suppression digest, schema and acknowledged recipient. Source revision changes are the intended comparison only within compatible identity; rename mapping must have captured Git/graph evidence. Branch/worktree/tool-version/suppression-policy mismatch or expired/unacknowledged baseline returns fresh compact snapshot with exact reason. Suppressed, skipped and unavailable observations are never classified resolved; only a completed comparable run can establish resolution. Return added/changed/resolved/unverified plus full current status. Bind cursors additionally to normalized query digest and current policy revision; revoked policy fails before continuation. Phase 73 owns acknowledgement meaning; existence in storage does not mean a model remembers it.

### 3.3 Usage receipt schema and migration

Extend the existing telemetry database, not a new ledger service. Add normalized request records keyed by `(provider, provider_request_id)` when available and deduplicated local invocation/attempt identity otherwise. Fields include parent invocation, model, input/output token counts, cache-read/write counts with provider semantic basis, embedding units separately, pricing source/version and currency/cost when known, duration, completion status and measurement source. Null means unavailable. Capture usage on errors/partial results when provider reports it. Keep original usage JSON only through the protected/redacted artifact policy, not verbose logs.

Add event metadata for artifact/version/hash, producer/delivery recipient, encoding/version, view/transform version, raw/rendered bytes and tokens, counted field/envelope boundary, and event kind (`constructed`, `cache_fill`, `cache_lookup`, `cache_reuse`, `returned_to_client`, `host_inserted`, `expanded`, `provider_request`). Existing events remain legacy observations; never infer missing provenance or turn costs into hits. Additive migration occurs only on authorized writer open; read-only readers inspect old schemas without schema/key/journal writes. Exact field definitions and provider conversion live with `TelemetryStore`/`ProviderResult`, reused by project snapshots, CLI, TUI and dashboard.

### 3.4 Compatibility and opt-in controls

Keep full canonical ToolResult available and default existing machine consumers unchanged. Compact views are explicit or negotiated host presentation; no removal of fields from downstream scan aggregation. Distillation acts on selected output views while retaining canonical/raw originals under existing retention and permissions. No arbitrary prose shortening of code, diagnostics, negative constraints or signed memory. Optional TOON is a text/presentation format, never replacement JSON-RPC. MCP structured/text compatibility is tested against actual supported host behavior.

LLMLingua worker is a fixed Rush-owned entrypoint, invoked with a user-configured engine Python executable and an approved local model directory; no agent-supplied executable or arbitrary code. Detect package version, load in offline/local-only mode, enforce timeout/memory limits and return measured counts plus source handle. Missing engine/model is unavailable and deterministic selection remains functional. Model preparation is separate consented setup with pinned artifact digest and license record; no import-time download. Default automatic adoption remains off until held-out fidelity/benefit gates pass.
